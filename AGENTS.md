# musicindex-studio

## What This Project Is

musicindex-studio is a part of the musicindex.org project. It replaces MSP 2.0.
An artist uses it to edit hosted Podcasting 2.0 music feeds directly.
Studio keeps the full collection of feeds for each user, and the method that writes each feed.

Studio has one core and two shells ([ADR 0001](docs/adr/0001-one-core-with-desktop-and-server-shells.md)):

- A desktop shell runs on the artist's machine.
- A server shell lets a host operator run a public service for web users.

The license is AGPL-3.0 ([ADR 0011](docs/adr/0011-agpl-license.md)).

## Where The Work Stands

On 2026-10-26, Phase 0 to Phase 11 are complete. The human tests of Phase 9 and milestone 11b are open. `studio-core` reads a feed into a lossless XML tree and a typed model, and writes each edit back. It has the encrypted secret vault, the SQLite collection, the release library, the connectors, the write pipeline and the announcement queue. The connectors are local folder, S3 and R2, SFTP, Blossom and nsite. `studio-api` serves the local JSON API and the UI. The UI has the album editor, a new release, the import of music files, the publisher feeds, the playlists and the live shows. A connected app can change a live show under a show grant of the user, through `/app/v1/`. A lossless import gives an MP3 enclosure and a FLAC alternative enclosure. `studio-desktop` runs them on a loopback address. `studio-server` serves them to many users on a public origin. It has five sign-in methods, a user folder for each account and a short vault window. Each shell sends a music file in parts, and the server is a home screen app. A connected app writes under a show grant through a grant vault, also while the user vault is locked.

The UI starts on Releases and shows the outline of an open feed. Below Releases, the left panel shows the levels of the publisher feeds: hosting, labels, then artists. At narrow width it is one stack.

## Commands

These four checks must pass before each commit. CI runs the same checks ([ADR 0042](docs/adr/0042-ui-models-with-node-tests.md) adds the fourth). `rust-toolchain.toml` pins the Rust version, and CI uses the same version ([ADR 0049](docs/adr/0049-the-rust-toolchain-is-pinned.md)).

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
node --test crates/api/ui-tests/*.test.mjs
```

On a computer with no Node.js, run `tools/node --test crates/api/ui-tests/*.test.mjs`. `tools/node` gets a pinned Node.js into `.studio-dev/tools/` at its first run. It also runs `tools/drive-ui.mjs`.

Run Studio locally. The command prints the UI address with its access token:

```sh
cargo run -p studio-desktop -- --data-dir .studio-dev/data
```

`--musicindex URL` selects a different musicindex API, such as a local test server.

Keep development and check data in `.studio-dev/` at the repository root. Git ignores this folder. Do not use `/tmp` for it.

## Design Philosophy

- Studio connects to hosts. It does not host files. The user can move files between hosts at any time ([ADR 0009](docs/adr/0009-studio-connects-to-hosts-and-moves-files.md)).
- The user controls the secrets. Only the user can open the vault. Under a show grant, the key of a connected app that the grant names opens a grant vault with one host secret ([ADR 0003](docs/adr/0003-user-unlocked-secret-vault.md), [ADR 0058](docs/adr/0058-grant-vaults-and-connected-apps-on-the-server.md), [ADR 0110](docs/adr/0110-a-connected-app-signs-each-request-with-its-own-key.md)).
- Feed identity does not change. Studio keeps the feed GUID and each item GUID ([ADR 0008](docs/adr/0008-feed-types-and-feed-identity.md)).
- No write occurs without a diff that the user has seen, or a change that a show grant of the user covers ([ADR 0007](docs/adr/0007-draft-diff-write-and-announce.md), [ADR 0054](docs/adr/0054-live-items-connected-apps-and-show-grants.md)).
- Studio uses the musicindex.org "Afterglow" visual direction ([ADR 0010](docs/adr/0010-studio-uses-the-afterglow-direction.md)).
- musicindex ADRs 0020 to 0029 own the interface rules that musicindex.org, Studio and HitIt share. They replace parts of ADR 0010, ADR 0029 and ADR 0037, and ADR 0010 names each part. A change to a shared rule needs a record in `../musicindex`.
- From 2026-11-11 the app v4vmm has the name HitIt (HitIt ADR 0096). In archived records, finished tasks, reviews, dated records and accepted ADRs, v4vmm means HitIt. The checkout of HitIt is `../HitIt`, and `../v4vmm` in these records means `../HitIt`.

## Working Rules

Each rule below states its owner. This file makes no rule.

Durable rules:

- The core crate has no HTTP server code and no UI code. It can make HTTP requests. Each feed rule is in the core ([ADR 0002](docs/adr/0002-rust-core-json-api-browser-ui.md)).
- The UI has no copy of a feed rule. An edit aid in the UI gives only a start value or a display value. The core can change a sent value at the draft save, or through a core route for one user action. Each task packet that changes the UI has the constraint "No feed rule in the UI (ADR 0065)", and its review examines each new UI function that changes the model. A test cannot tell a feed rule from an edit aid ([ADR 0065](docs/adr/0065-the-core-applies-each-feed-rule.md)).
- A connector gets its secrets from the vault only. No secret is in a log, an API response or the collection database ([ADR 0003](docs/adr/0003-user-unlocked-secret-vault.md), [ADR 0006](docs/adr/0006-connectors-and-the-v1-set.md)).
- A write to a host occurs only through `pipeline::write_draft`. It uses the ID of the diff that the user approved, or of a diff that a show grant covers ([ADR 0007](docs/adr/0007-draft-diff-write-and-announce.md), [ADR 0015](docs/adr/0015-connector-interface-and-write-pipeline.md), [ADR 0054](docs/adr/0054-live-items-connected-apps-and-show-grants.md)).
- A read of a feed from its host moves a draft with no edits to the file that Studio read. Each other draft keeps its base ([ADR 0007](docs/adr/0007-draft-diff-write-and-announce.md) item 6). The core merges the hosted file into a draft only when the user selects it, and the user reviews the result ([ADR 0129](docs/adr/0129-a-draft-takes-a-change-of-the-hosted-file.md)).
- A read and a write with no edit give the same bytes. The writer changes only the elements that the user changed, and a change of a feed also sets `lastBuildDate`. The corpus tests enforce the first rule ([ADR 0008](docs/adr/0008-feed-types-and-feed-identity.md), [ADR 0012](docs/adr/0012-lossless-tree-with-a-typed-model.md), [ADR 0127](docs/adr/0127-a-changed-feed-gets-a-new-build-date.md)).
- The UI loads no script, style, font or frame from other servers, and it has no build step ([ADR 0016](docs/adr/0016-ui-without-a-build-step.md)). Images and audio load from their `https` addresses ([ADR 0109](docs/adr/0109-images-and-audio-load-from-their-hosts.md), task 072). A test of the page rule enforces this.
- UI logic that a test examines is in a model module with no Preact and no browser state. The Node tests in `crates/api/ui-tests/` examine it ([ADR 0042](docs/adr/0042-ui-models-with-node-tests.md)).
- In local mode, each `/api/` request needs the access token, and each request needs a loopback `Host` ([ADR 0017](docs/adr/0017-local-api-access.md)). Tests enforce this. Each `/app/v1/` request needs a signed event of the key of a connected app, and no other route accepts it ([ADR 0110](docs/adr/0110-a-connected-app-signs-each-request-with-its-own-key.md), task 073). Studio keeps no secret of an app.

- The track page shows `podcast:season` as "Disc", in a collapsed entry with the Experimental badge of musicindex ADR 0034 ([ADR 0080](docs/adr/0080-the-season-of-a-track-is-an-experimental-disc-setting.md)).
- A copy of an album keeps no feed GUID and no item GUID of its source ([ADR 0077](docs/adr/0077-a-new-album-can-start-from-an-album.md)).
- Each date and time field is a `DateTimeField` of `app.js`, in the local time of the browser. The UI sends RFC 3339 text with the local offset. The core writes `pubDate` from `pub_date_time`, and a `pubDate` that the user does not change keeps its bytes ([ADR 0093](docs/adr/0093-dates-and-times-use-a-picker-in-local-time.md)).
- "Properties" of an audio file shows its size, type and duration as text. The boxes show only after "Advanced" and its warning, also for a missing value ([ADR 0130](docs/adr/0130-the-facts-of-an-audio-file-stay-locked.md)).
- The field "Duration" edits `duration_seconds` as minutes and seconds. The core writes a changed `itunes:duration` as `HH:MM:SS`, and a duration that the user does not change keeps its bytes ([ADR 0094](docs/adr/0094-a-duration-is-edited-as-minutes-and-seconds.md)).
- Settings has a "UI scale" with the five levels of HitIt, with a mouse only. The browser keeps the level. A release tile has a minimum width of 200 px ([ADR 0134](docs/adr/0134-a-ui-scale-and-larger-release-tiles.md)).
- One check box at the Write button tells Podcast Index and sends a podping. Studio remembers the last choice. A granted write always announces ([ADR 0136](docs/adr/0136-one-announcement-choice-at-the-write.md)).
- The part "Other" of the share bar holds at most 10 %, and a part of 5 % or more stays in the bar. The bar has a maximum of 20 parts and "Other" ([ADR 0133](docs/adr/0133-the-share-bar-shows-the-divisions-of-a-payment.md)).
- The writer always escapes `&` and `<`, and `"` in an attribute value. A changed value keeps the form of its source for `'`, `"` in text and `>`: the entity or the literal character. A value with no source form uses the entity ([ADR 0115](docs/adr/0115-a-changed-value-keeps-the-escape-form-of-its-source.md)).
- The default data folder of the desktop holds each collection in `collections/{folder}/`. `--data-dir` opens one folder as one collection, with no move. Only the desktop app has the routes and the section "Collections". "Open" restarts the app under the "Quit" rules, and only the open collection runs. A new collection has its own vault and its own library, and a copy has the vault of its source and no connected app, show grant or queued announcement ([ADR 0149](docs/adr/0149-the-desktop-app-has-many-collections.md)).
- The desktop app is a Tauri window on the local API. It exposes no Tauri command to the page, and the UI has no code for Tauri. A left click on the tray icon opens the window, through the `ksni` backend on Linux. The first close asks "Keep in Tray" or "Quit on Close", and Settings changes the choice. With no tray host, a close quits. On Linux with an NVIDIA card, the app starts itself again one time with `WEBKIT_DISABLE_DMABUF_RENDERER=1`. On Linux, the app gets a drop and gives the file to the page through a one-time route of the local router, and a script of the window connects Ctrl+Z to the undo command and makes the toolbar opaque. The AppImage holds a fixed list of GStreamer plugins, and the release check refuses a different set. One shell at a time uses a data folder, through a lock file. The default port of the desktop shells is 42069, else a free port ([ADR 0124](docs/adr/0124-the-desktop-app-is-a-tauri-window-on-the-local-api.md)).
- With a mouse, a file field shows a drop hint, and each sheet that takes a file has a drop area. During a file drag each target has a light outline. A file drag that no target takes changes nothing ([ADR 0125](docs/adr/0125-each-file-target-shows-that-it-takes-a-drop.md)).
- The core refuses a write with a bad move link, and the user has no override. A move reads its destination after the feed is on the new host and before the pointer. A self link that the draft does not change gets a notice, and a granted write gets no check. Condition 5 waits for a route in Stophammer ([ADR 0126](docs/adr/0126-studio-refuses-a-bad-move-link.md)).
- A page checks its feeds for a change from outside when it opens, with no worker and no vault. The core compares the public file with the last file that Studio read or wrote, and the check writes nothing. A feed page also compares the address of musicindex. A check box in Settings stops each request ([ADR 0150](docs/adr/0150-studio-shows-a-change-from-outside-when-a-page-opens.md)).
- After the feed list loads and at each open of Releases, Studio checks each feed with a public address, also the artist, label and hosting pages. One store in the shell keeps the results. A row of the left panel shows the most urgent mark of its feed and its releases: changed outside Studio, changes not written, or not checked. An up-to-date row has no mark ([ADR 0165](docs/adr/0165-the-left-panel-marks-the-state-of-each-feed.md)).

- After a move, the feed on the new host has a tag that names its own URL, and Review warns at each return. A new tag goes directly after `<channel>`. Stophammer ADR 0083 owns the rule of the index ([ADR 0128](docs/adr/0128-a-moved-feed-names-its-own-address.md)).
