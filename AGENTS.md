# musicindex-studio

## What This Project Is

musicindex-studio is a part of the musicindex.org project. It replaces MSP 2.0.
An artist uses it to edit hosted Podcasting 2.0 music feeds directly.
Studio keeps the full collection of feeds for each user, and the method that writes each feed.

Studio has one core and two shells ([ADR 0001](docs/adr/0001-one-core-with-desktop-and-server-shells.md)):

- A desktop shell runs on the artist's machine.
- A server shell lets a host operator run a public service for web users.

The license is AGPL-3.0 ([ADR 0011](docs/adr/0011-agpl-license.md)).

## Where The Work Stands

Phase 0 to Phase 11 are complete. `studio-core` reads a feed into a lossless XML tree and a typed model, and writes each edit back. It has the encrypted secret vault, the SQLite collection, the release library, the connectors, the write pipeline and the announcement queue. The connectors are local folder, S3 and R2, SFTP, Blossom and nsite. `studio-api` serves the local JSON API and the UI. The UI has the album editor, a new release, the import of music files, the publisher feeds, the playlists and the live shows. A connected app can change a live show under a show grant of the user, through `/app/v1/`. A lossless import gives an MP3 enclosure and a FLAC alternative enclosure. `studio-desktop` runs them on a loopback address. `studio-server` serves them to many users on a public origin. It has five sign-in methods, a user folder for each account and a short vault window. Each shell sends a music file in parts, and the server is a home screen app. A connected app writes under a show grant through a grant vault, also while the user vault is locked.

The UI starts on Releases and shows the outline of an open feed. Below Releases, the left panel shows the levels of the publisher feeds: hosting, labels, then artists. At narrow width it is one stack.

## Commands

`tools/gate.sh` is the commit gate. It must pass before each commit. It runs `cargo fmt`, `cargo clippy`, the Rust tests, the Node tests of the UI models ([ADR 0042](docs/adr/0042-ui-models-with-node-tests.md)) and the ADR link guard of the `project-baseline` skill. The guard runs its bar check from ADR 0214 (`--bar-from 0214`). CI runs the first four checks, because the guard script is not in this repository. `rust-toolchain.toml` pins the Rust version, and CI uses the same version ([ADR 0049](docs/adr/0049-the-rust-toolchain-is-pinned.md)).

```sh
tools/gate.sh
```

`tools/node` gets a pinned Node.js into `.studio-dev/tools/` at its first run. It runs the Node tests and `tools/drive-ui.mjs`.

Run Studio locally. The command prints the UI address with its access token:

```sh
cargo run -p studio-desktop -- --data-dir .studio-dev/data
```

`--musicindex URL` selects a different musicindex API, such as a local test server.

Keep development and check data in `.studio-dev/` at the repository root. Git ignores this folder. Do not use `/tmp` for it.

## Design Philosophy

- Studio connects to hosts. It does not host files. The user can move files between hosts at any time ([ADR 0009](docs/adr/0009-studio-connects-to-hosts-and-moves-files.md)).
- The user controls the secrets. Only the user can open the vault. Under a show grant, the key of a connected app that the grant names opens a grant vault with one host secret ([ADR 0003](docs/adr/0003-user-unlocked-secret-vault.md), [ADR 0058](docs/adr/0058-grant-vaults-and-connected-apps-on-the-server.md), [ADR 0110](docs/adr/0110-a-connected-app-signs-each-request-with-its-own-key.md)).
- Feed identity does not change. Studio keeps the feed GUID and each item GUID ([ADR 0008](docs/adr/0008-feed-types-and-feed-identity.md)).
- No write occurs without a diff that the user has seen, or a change that a show grant of the user covers ([ADR 0007](docs/adr/0007-draft-diff-write-and-announce.md), [ADR 0205](docs/adr/0205-publisher-feeds-announcements-and-show-grants.md) item 53).
- Studio uses the musicindex.org "Afterglow" visual direction ([ADR 0010](docs/adr/0010-studio-uses-the-afterglow-direction.md)).
- musicindex ADR 0021 to ADR 0023, ADR 0026, ADR 0028, ADR 0068 and ADR 0080 own the interface rules that musicindex.org, Studio and HitIt share. They replace parts of ADR 0010, ADR 0029 and ADR 0037, and ADR 0010 names each part. A change to a shared rule needs a record in `../musicindex`.
- From 2026-11-11 the app v4vmm has the name HitIt (HitIt ADR 0096). In archived records, finished tasks, reviews, dated records and accepted ADRs, v4vmm means HitIt. The checkout of HitIt is `../HitIt`, and `../v4vmm` in these records means `../HitIt`.

## Working Rules

Each rule below states its owner. This file makes no rule.

Durable rules:

- The core crate has no HTTP server code and no UI code. It can make HTTP requests. Each feed rule is in the core ([ADR 0002](docs/adr/0002-rust-core-json-api-browser-ui.md)).
- The UI has no copy of a feed rule. An edit aid in the UI gives only a start value or a display value. The core can change a sent value at the draft save, or through a core route for one user action. Each task packet that changes the UI has the constraint "No feed rule in the UI (ADR 0065)", and its review examines each new UI function that changes the model. A test cannot tell a feed rule from an edit aid ([ADR 0065](docs/adr/0065-the-core-applies-each-feed-rule.md)).
- A connector gets its secrets from the vault only. No secret is in a log, an API response or the collection database ([ADR 0003](docs/adr/0003-user-unlocked-secret-vault.md), [ADR 0006](docs/adr/0006-connectors-and-the-v1-set.md)).
- A write to a host occurs only through `pipeline::write_draft`. It uses the ID of the diff that the user approved, or of a diff that a show grant covers ([ADR 0007](docs/adr/0007-draft-diff-write-and-announce.md), [ADR 0015](docs/adr/0015-connector-interface-and-write-pipeline.md), [ADR 0205](docs/adr/0205-publisher-feeds-announcements-and-show-grants.md) item 53).
- A read of a feed from its host moves a draft with no edits to the file that Studio read. Each other draft keeps its base ([ADR 0007](docs/adr/0007-draft-diff-write-and-announce.md) item 6). The core merges the hosted file into a draft only when the user selects it, and the user reviews the result ([ADR 0129](docs/adr/0129-a-draft-takes-a-change-of-the-hosted-file.md)).
- A read and a write with no edit give the same bytes. The writer changes only the elements that the user changed, and a change of a feed also sets `lastBuildDate`. The corpus tests enforce the first rule ([ADR 0008](docs/adr/0008-feed-types-and-feed-identity.md), [ADR 0012](docs/adr/0012-lossless-tree-with-a-typed-model.md), [ADR 0127](docs/adr/0127-a-changed-feed-gets-a-new-build-date.md)).
- The UI loads no script, style, font or frame from other servers, and it has no build step ([ADR 0016](docs/adr/0016-ui-without-a-build-step.md)). Images and audio load from their `https` addresses ([ADR 0109](docs/adr/0109-images-and-audio-load-from-their-hosts.md), task 072). A test of the page rule enforces this.
- UI logic that a test examines is in a model module with no Preact and no browser state. The Node tests in `crates/api/ui-tests/` examine it ([ADR 0042](docs/adr/0042-ui-models-with-node-tests.md)).
- In local mode, each `/api/` request needs the access token, and each request needs a loopback `Host` ([ADR 0017](docs/adr/0017-local-api-access.md)). Tests enforce this. Each `/app/v1/` request needs a signed event of the key of a connected app, and no other route accepts it ([ADR 0110](docs/adr/0110-a-connected-app-signs-each-request-with-its-own-key.md), task 073). Studio keeps no secret of an app.
- A secret value stays hidden until the user selects its eye button. A secret value is in a vault, or Studio shows it one time only. A Node test finds a secret field that does not use the component of `app.js` ([ADR 0078](docs/adr/0078-a-secret-value-stays-hidden-until-the-user-shows-it.md)).
- When Studio has a picker for a type of value, each location that edits that type of value uses that picker, and no location has its own input for it. A Node test refuses a plain field for a Nostr key in the link forms of a person ([ADR 0123](docs/adr/0123-one-type-of-value-has-one-picker.md)).
- The vault refuses a passphrase with fewer than 12 characters or a zxcvbn score below 3. The UI gives no advice on how to make a passphrase ([ADR 0018](docs/adr/0018-passphrase-strength-and-error-color.md)).
- An entity color is not a general accent. An error uses the `--error` token, not an entity color ([ADR 0018](docs/adr/0018-passphrase-strength-and-error-color.md)). All functions work from the keyboard ([ADR 0010](docs/adr/0010-studio-uses-the-afterglow-direction.md)). A control has the target size of its profile: 28 px with a mouse and 44 px with touch (musicindex ADR 0068 R-SCALE-4 and ADR 0068 R-TARGET-1). A test enforces the token. Each text size is a `--text-*` token (musicindex ADR 0068 R-SCALE-4). With a mouse, a token has the macOS size of ADR 0068 R-TYPE-1. With touch, it has the iOS size of ADR 0068 R-TYPE-1. A Node test compares the tokens with `tokens.json` and refuses a free `font-size`. With touch, a field has the Body size of 17 px, so that iOS Safari does not zoom the page ([task 062](docs/tasks/studio-v1-task-062-field-text-on-touch.md)). A Node test enforces the last rule of `styles.css` that gives it.
- The type dot and the entity colors follow musicindex ADR 0032 R-DOT-1. A test compares `styles.css` with `crates/api/ui/assets/tokens.json`, the copy from `../musicindex-assets` (musicindex ADR 0032 R-DOT-2).
- A publisher feed shows each of its roles, for example "Artist" or "Artist · Label". The interface shows the word "publisher" only as an RSS name (musicindex ADR 0033 R-WORD-3 and R-WORD-4, musicindex ADR 0037 R-WORD-7, [ADR 0084](docs/adr/0084-the-label-of-a-feed-lists-each-role.md)). A Node test examines the UI text.
- A publisher feed has a set of the eight roles of musicindex ADR 0067 item 43, in the sequence of musicindex ADR 0036. A role that Studio infers from the feed has a hollow dot until the user confirms it. A release in the collection that gives the first role in its link also fills the dot. Artist, label and hosting are the choices of the Role menu and of the form of a new publisher feed ([ADR 0082](docs/adr/0082-a-publisher-feed-has-a-set-of-roles.md), [ADR 0083](docs/adr/0083-hosting-is-a-first-class-role.md), [ADR 0087](docs/adr/0087-the-two-sides-of-a-link-confirm-a-role.md)).
- The section Releases of a publisher feed with a file host ends with the row "Add an Album" for an artist, or "Add a Release" for each other role. The row does not show with a first-step row. The list view of a group has the same action as a button. A new album or playlist from these actions or from a first-step row becomes a release of the feed before its page opens. The title of the sheet that makes a feed names the page, for example "Make a new release" ([ADR 0164](docs/adr/0164-the-releases-of-a-publisher-feed-have-an-add-row.md)).
- A confirmation is a sheet of Studio, never the browser box `confirm()`. Its texts are in `confirms.js`. A Node test finds each call of `confirm(` (musicindex ADR 0023 R-CONFIRM-1, [task 057](docs/tasks/studio-v1-task-057-confirmation-sheets.md)).
- In a row of buttons, a destructive button is the first button, with a larger space after it, and the safe action is the last button. A confirmation sheet gives the first focus to its safe button, and a destructive button is never a `submit` button. A row with only destructive buttons shows one "Remove…" button with a menu. A button that replaces saved choices is destructive. A Node test scans the rows (musicindex ADR 0064 R-ACT-8 to R-ACT-12, [ADR 0193](docs/adr/0193-a-destructive-button-is-the-first-button-of-its-row.md)).
- A button label uses title case. Each other text uses sentence case. A Node test finds a button label that is not in title case (musicindex ADR 0023 R-CASE-1, [task 058](docs/tasks/studio-v1-task-058-title-case-buttons.md)).
- Each labeled button has a role: primary, action, normal or destructive. A button with a text label is not a `button quiet` ([ADR 0037](docs/adr/0037-button-roles.md)).
- Each entry of a list shows as one summary line, and one entry of a list is open at a time. A section that the user does not change in each visit starts collapsed, with a summary line ([ADR 0028](docs/adr/0028-summary-lines-and-one-open-entry.md)). A test enforces the `details` elements.
- Each section of a page has a tier: identity, content, details, setup, then limits. A page shows its sections in the sequence of their tiers. `crates/api/ui/pages.js` gives the sections, and a Node test enforces the sequence. A new section needs a tier, not an ADR ([ADR 0071](docs/adr/0071-settings-is-a-destination-and-each-page-orders-its-sections-by-tier.md)).
- The editor uses a maximum of three background levels: the page, a group and an open entry. A level changes the fill only, and a border does not identify a level. A group holds rows, and thin separators divide them ([ADR 0029](docs/adr/0029-editor-pages-toolbar-and-three-levels.md)). Before each commit of a UI packet, the visual check runs `$edges()` of `tools/drive-ui.mjs` to find content at the edge of a group. At 390 px with touch, it also runs `$fieldText()` and `$overflow()`. CI has no browser, so no commit check runs it.

Situational rules:

- The v1 connectors are local folder, SFTP, S3 and R2, Blossom and nsite, and the optional self-hosted file host. The Git pages connector comes after v1 ([ADR 0006](docs/adr/0006-connectors-and-the-v1-set.md), [ADR 0043](docs/adr/0043-phase-9-connectors-and-the-interface-change.md)).
- No deletion on a host occurs before each new file passes the confirmation ([ADR 0043](docs/adr/0043-phase-9-connectors-and-the-interface-change.md)).
- A move deletes no old copy at its write. The old copy stays until the user reviews its deletion, and Studio never deletes it by itself. A move is ready after its waiting time, unless musicindex gives a different feed address ([ADR 0148](docs/adr/0148-a-move-keeps-the-old-files-until-the-user-reviews-the-deletion.md)).
- No test sends a request to a host outside the computer. Each connector passes the trait suite against a local test server ([ADR 0045](docs/adr/0045-phase-9-crates-test-servers-and-host-forms.md)).
- With a mouse, Back and Forward are filled circles (musicindex ADR 0080 R-NAV-4). A Node test examines their class.
- Each sort menu names both directions of each sort as entries in words, for example "Newest" then "Oldest", and no list has a reverse icon. The address keeps the direction of Releases, and a feed group keeps its own sort and direction (musicindex ADR 0054 R-LIST-13, musicindex ADR 0043 R-LIST-6, [ADR 0155](docs/adr/0155-the-sort-menu-names-both-directions.md)). Node tests examine the entries, the names and the sequence.
- The People list has "A to Z", the default, and "Newest", in both directions, and no view icons. It keeps its sort in the navigation record. Each sort by name reads a number as a number, in the language of the reader, and the payees sort by name. A list with no row in musicindex ADR 0053 R-LIST-9 has no control. Node tests examine the orders ([ADR 0153](docs/adr/0153-the-people-list-has-a-sort-and-names-sort-with-numbers.md), musicindex ADR 0053).
- After a write of one feed from Review, Review stays open with the result panel. A feed with no public address gets the warning "Listeners cannot get it yet." and **Put It Online…** ([ADR 0217](docs/adr/0217-a-new-artist-sees-the-result-of-a-write-the-payment-types-and-an-undo-of-a-merge.md) items 1 to 6). When Review stops the write for a missing artist or publisher page, the refusal panel links the page in Review, and the write button shows disabled ([ADR 0218](docs/adr/0218-a-page-link-in-review-and-a-suggestion-starts-with-no-person.md) items 1 to 9).
- The page of a release shows a checklist of tracks, cover, audio files and payment recipient while one is missing. The rows come from findings of the core, which also show on the Check tab. A recipient address in the format of the other type gives a finding, and its repair changes the type in the draft ([ADR 0219](docs/adr/0219-a-release-checklist-and-a-check-of-the-address-type.md) items 1 to 10).
- The header of a release page links `https://musicindex.org/#feed={podcast:guid}` only when the outside check of the page says that Music Index holds the feed ([ADR 0220](docs/adr/0220-a-release-page-links-its-page-on-music-index.md)).
- An error notice of an action names the action, gives one step from the error code and has "Try Again" when a new attempt can help. A failed import row has "Try Again", and a list that cannot load says so in the place of an empty list. The raw text of the error is in a closed fold "Details" ([ADR 0222](docs/adr/0222-errors-give-a-step-terms-get-a-hint-and-the-first-run-has-two-stages.md) items 1 to 5, musicindex ADR 0085 R-MSG-1).
- A term from the feed standard keeps its word and gets a hint line where a new artist first sees it. The first-run sheet has two stages, and its button "Make the Page" makes the page ([ADR 0222](docs/adr/0222-errors-give-a-step-terms-get-a-hint-and-the-first-run-has-two-stages.md) items 6 to 10).
- The draft status, "Versions" and "Review" stay in the toolbar at all scroll positions and widths. The left panel holds the destinations, or the outline of the open feed. People, File hosts, Settings and Lock Studio always show at its bottom ([ADR 0203](docs/adr/0203-people.md) item 36). On a server with a locked vault, "Unlock Studio" is in the place of "Lock Studio". At 760 px or less, Studio is one stack with a root page and an outline page, and no menu button ([ADR 0206](docs/adr/0206-the-shell-and-the-editor-pages.md) items 1 to 15, musicindex ADR 0080, [ADR 0207](docs/adr/0207-recipients-change-sets-and-wallets.md) item 8).
- Each fixed destination shows its Lucide icon, and no destination row shows a type dot. A UI text names a connector "file host". The word "host" alone is the role `host` ([ADR 0092](docs/adr/0092-file-hosts-and-the-destination-icons.md)).
- A change set applies one recipient operation, or one move of releases ([ADR 0148](docs/adr/0148-a-move-keeps-the-old-files-until-the-user-reviews-the-deletion.md)), to many feeds. The core calculates each split, and Discard puts back each draft from before the change. Each feed of a change set writes through `pipeline::write_draft` with the ID of its own diff ([ADR 0207](docs/adr/0207-recipients-change-sets-and-wallets.md) items 24 to 33).
- A `node` recipient and an `lnaddress` recipient with the same keysend lookup result are one recipient, and an operation acts on each address of that recipient. The core makes the lookup and keeps the result in the collection. An operation that puts an `lnaddress` recipient into a value block writes `method="lnaddress"`. Change address and Add to All Releases need a type ([ADR 0207](docs/adr/0207-recipients-change-sets-and-wallets.md) items 34 to 47, [ADR 0096](docs/adr/0096-add-to-an-artist-or-label.md)). A suggestion of a Lightning address is a guess with a keysend lookup that gives the wallet, and the collection keeps no lookup of a guess ([ADR 0097](docs/adr/0097-studio-suggests-the-lightning-address-of-a-wallet.md)).
- The module `people` keeps the people of one user. It writes no feed, and a value from a person is a start value in a feed. Studio makes no link of a person without the user. An artist or a label is its publisher feed, not a person. Each operation of a person is a change set, and the core gives a wallet its type from its address ([ADR 0203](docs/adr/0203-people.md) items 1 to 3, 11, 12, 19 and 26). A suggestion groups the items of one name, and one person can collect the items of many suggestions ([ADR 0203](docs/adr/0203-people.md) items 13 to 16, 30 and 38 to 40). The menu "Person" of a suggestion starts on "Select a person" when no person has its name ([ADR 0218](docs/adr/0218-a-page-link-in-review-and-a-suggestion-starts-with-no-person.md) items 10 to 14). A delete of a person changes no feed ([ADR 0203](docs/adr/0203-people.md) item 33). The merge sheet starts with no selected person. After a merge, **Undo** puts back each row of the two persons, and the core keeps the undo data of the last merge only ([ADR 0217](docs/adr/0217-a-new-artist-sees-the-result-of-a-write-the-payment-types-and-an-undo-of-a-merge.md) items 12 to 17). "Hide This Suggestion" hides a suggestion, the fold "Hidden suggestions" lists it, and "Show Again" removes the dismissal. A credit row of a suggestion sheet has the form of ADR 0203 item 54 ([ADR 0203](docs/adr/0203-people.md) items 21, 37 and 43).
