# Music Index Studio 0.1.0-rc.10

This candidate closes the gaps of the first People test ([task 067](../tasks/studio-v1-task-067-people-test-findings.md)) and the findings of the security audit of 2026-11-01 (tasks 068 to 073). It comes after 0.1.0-rc.9.

## What changed

### People

- Studio makes one suggestion of each name. "Add to a Person" adds the items of a suggestion to a person that you have ([ADR 0103](../adr/0103-one-person-collects-the-items-of-many-suggestions.md)).
- The page of a person has "More from your feeds", with the items of your feeds that match the person. "Merge with a Person" makes two people into one.
- "Delete Person" deletes a person and changes no feed ([ADR 0102](../adr/0102-delete-a-person-changes-no-feed.md)). The operation "Remove" has the new name "Remove from Feeds".
- Each Nostr key shows the name of its profile. A copy button copies the full key or address.
- A `lud16` suggestion names its profile and its key. The menu "Default address" shows each address of the wallet, also an address that no feed uses.
- On the server, the People page starts with a note: the People data is not encrypted on the server ([ADR 0108](../adr/0108-people-data-at-rest-stays-plain.md)).

### Account protection

- These changes need an unlock in the last 5 minutes: a new passphrase, the vault key for a signer, and the add or removal of a sign-in method. The deletion of the account and the add of a connected app also need it. Studio then asks you to unlock again ([ADR 0106](../adr/0106-a-sensitive-account-change-needs-a-recent-unlock.md)).
- After a new passphrase or the removal of a method, the server ends each other session of the account.
- The limits of failed sign-ins apply to each pair of account and address (10 in each hour) and to each account (100 in each hour). Thus, a third party cannot easily block the sign-in of a user. The challenge routes permit 30 challenges from each address in each 5 minutes.
- Each shell process cannot write a core dump. The data folders and the vault files are private to their owner on Unix ([ADR 0104](../adr/0104-key-material-stays-off-the-disk.md)).

### Files on the server

- By default, the server keeps an audio file or an image only until the write that sends it, for a maximum of 7 days. The option `--hold-assets on` keeps the behavior of 0.1.0-rc.9 ([ADR 0105](../adr/0105-a-public-server-holds-no-assets.md)).
- The Files page shows the status of each file. "Download to This Device" saves a file to your device. "Add the File Again" puts back a file that the server removed.
- On the server, Settings shows "Files on this server" in the place of "Library".

### Account export and import

- Settings has "Export Account" on the server and "Export Studio" on the desktop. The archive holds your collection, your library and your vault files as they are ([ADR 0107](../adr/0107-a-user-can-export-and-import-an-account.md)).
- At sign-up on the server, and on a new Studio desktop, you can import an archive. An import makes a new account. It writes nothing to a host and changes no feed.
- When only your passkeys open the vault, the export first makes a recovery key, because a passkey works only on its server.

### Images, audio and connected apps

- Images and audio load directly from their `https` addresses, not through Studio ([ADR 0109](../adr/0109-images-and-audio-load-from-their-hosts.md)).
- A connected app has its own key pair, and it signs each request with that key. You connect an app with a one-time pairing text. Each show grant names one app ([ADR 0110](../adr/0110-a-connected-app-signs-each-request-with-its-own-key.md)).
- An app that you connected before this candidate shows "Connect Again". Studio refuses its token, and each grant from before stops. Connect the app again, and give the grant again.
- The server image is built from a pinned base image, and the deploy uses the digest of the image.

## What to test

1. Open the person "HeyCitizen". Add the items of "More from your feeds". Then use "Add to a Person", "Merge with a Person" and "Delete Person" one time each. Make sure that no feed gets a draft.
2. Make sure that each Nostr key shows its profile name, and that the copy button copies the full `npub`.
3. Sign in on two devices. Change the passphrase on one device. Make sure that the other device goes to the sign-in page.
4. Wait more than 5 minutes after an unlock, then select "Add a Passkey". Make sure that Studio asks you to unlock again.
5. From a phone, add a track and write the draft. Make sure that the Files page shows "On its file host". Then save the file with "Download to This Device".
6. Play a track. Make sure that the network panel of the browser shows the request to the file host, not to Studio.
7. Export the account from `studio.musicindex.org`. Import it into Studio desktop, open a draft and write it.
8. On the VPS, run `docker exec` into the container. Make sure that `stat -c %a /data /data/users /data/users/*/vault.json` gives 700, 700 and 600. Make sure that `grep core /proc/1/limits` gives a core limit of 0.

## Known gaps

- The live publisher does not have the client of ADR 0110. Until it has that client, a live show cannot change through a connected app. The human test of task 073 waits for that client.
- `GET /app/v1/shows` gives no start time and no status for a show on a file host that needs a secret.
- On a new Studio desktop, "Import an Account" shows only after the first-run pages.
- An import with a NIP-07 or NIP-46 signer has had no run in a browser.
- The human tests of Phase 12 (the server shell) and of tasks 065 to 067 stay open.
