# Music Index Studio 0.1.0-rc.13

This candidate shows each review in words, and marks the changed part of each line ([ADR 0114](../adr/0114-the-review-shows-the-changes-in-words-and-marks-the-changed-part-of-a-line.md)). A changed value keeps the form of its apostrophes ([ADR 0115](../adr/0115-a-changed-value-keeps-the-escape-form-of-its-source.md)). It also corrects three faults of "Correct the Feeds". It comes after 0.1.0-rc.12.

## What changed

### The review in words

- The sheet "Review changes" has the menu **View**, with **Simplified** and **Detailed**. Studio keeps your selection on this device, and each review starts on it.
- **Simplified** is the default. It shows **What changes** first, in the words of the editor, for example "Title: Old name → New name". Then it shows **Changed lines**.
- When many entries get the same new value, **What changes** gives one line, for example "6 credits get the Nostr key City Radio". Select the line "4 more credits" to see the others.
- A Nostr key shows the profile name and the short key. When the profile name is not the name of the credit, Studio shows "The profile name is not "{name}". Check this key." This warning also shows on a track credit.
- When a change is in the file but not in the list, the list ends with a row, for example "1 more change in the XML". Select **Detailed** to see each changed line.
- **Detailed** shows only the changed lines.

### The marked lines

- A line that starts with `+` is new, and a line that starts with `−` goes out. A line that starts with `±` has a changed part, and Studio marks that part. For example, a new Nostr key on a credit marks only ` npub="…"`.
- Studio shows three lines around each change. Select "Show N more lines" to open a run of hidden lines.
- Select **Show the Whole File** to see each line. Select **Show Only the Changes** to go back.

### A changed value keeps its apostrophes

- Before, a changed title or attribute wrote each apostrophe as `&apos;`, also when the feed had the plain character `'`. The review then marked an apostrophe that you did not change.
- A changed value keeps the form of the value that it replaces, for `'`, for `"` in text and for `>`. A feed from MSP 2.0 keeps `&apos;`, and a feed with plain apostrophes keeps `'`.
- A new value uses the entity, as before. The two forms are correct XML, and each feed reader of Studio reads the two forms.

### Correct the Feeds

- The last change of the sheet reads "Replace other addresses named "{name}"". Its line gives the number of these payments and your default address, and says to select it only when that address is yours too. The notes of 0.1.0-rc.12 gave this change, but that candidate did not have it.
- The menu "Nostr key" starts on the first key of the person with no profile warning. Before, it started on the first key, and a key of a different profile could go to each credit. When each key has the warning, no key is selected, and the line shows the warning.
- After an unlock, the review of a change set reads the change set again. Before, a feed that the locked vault blocked kept the text "Studio cannot write this feed while the vault is locked", and Write left it out.

## What to test

1. Change the title of an album. Open **Review**, and make sure that **What changes** gives the title before and after the change.
2. In **Changed lines**, make sure that only the changed words have a mark.
3. Change a title with an apostrophe in a feed from MSP 2.0. Then do the same in a feed with plain apostrophes. In each review, make sure that the apostrophe has no mark.
4. Open a person with a credit key that is not the key of the person. Open "Check your feeds", then "Correct N Feeds".
5. Make sure that "Nostr key" starts on a key with no warning.
6. In the review, make sure that "What changes" gives one line for the credits, and the warning when it applies.
7. Select **Detailed**, then **Show the Whole File**, then **Show Only the Changes**.
8. Open the review of one feed in the editor. Make sure that it starts on the view that you selected last.
9. Lock Studio, open the review of a change set, then unlock. Make sure that each feed can be written.

## Known gaps

- **What changes** shows the fields of the editor only. A change that the editor does not show is in the row "N more changes in the XML".
- The human tests of Phase 12 (the server shell), of tasks 065 to 078, and of 0.1.0-rc.10 to 0.1.0-rc.12 stay open.
