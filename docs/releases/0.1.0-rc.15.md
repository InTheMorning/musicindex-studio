# Music Index Studio 0.1.0-rc.15

This candidate lets you find a Nostr key by name on the page of a person, with the same sheet as the editor ([ADR 0123](../adr/0123-one-type-of-value-has-one-picker.md)). It comes after 0.1.0-rc.14.

## What changed

### One picker for a Nostr key

- Before, **Add a Nostr Key** on the page of a person had only a text field for an `npub` key.
- In this candidate, it opens the sheet **Find a Nostr profile**, as in the editor. Type a name, an `npub` key or a NIP-05 address, and select **Search**. Each result shows the picture, the name and the sources of the profile. Select a result to add its key to the person.
- **Add a Credit Name** has the row **Nostr key**. The row opens the same sheet, and the selected key goes in the credit name.
- When a musicindex feed gives no Nostr key, **Find on musicindex** tells you to use **Add a Nostr Key** to search the Nostr profiles. With this change, that text is correct.

### The rule

- When Studio has a picker for a type of value, each location that edits that type of value uses that picker. A Node test refuses a plain field for a Nostr key in the forms of a person.

## What to test

1. On a phone, open the page of a person, and select **Add a Nostr Key**.
2. Type the name of the person, and select **Search**.
3. Select the correct profile. Make sure that the key shows in the head of the page.
4. Select **Add a Credit Name**, type a name, and select the row **Nostr key**.
5. Search, and select a profile. Make sure that the row shows the key.
6. Select **Add the Credit Name**. Make sure that the credit name shows with its key.

## Known gaps

- On the page of a person, the sheet does not offer to use the profile name or the profile picture. Type these values in the fields, then select **Save**.
- The human tests of Phase 12 (the server shell), of tasks 065 to 084 and of 0.1.0-rc.10 to 0.1.0-rc.14 stay open.
- The server part of the human test of task 086 stays open.
