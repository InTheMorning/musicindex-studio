# Music Index Studio 0.1.0-rc.18

This candidate corrects the findings of the [human test of 0.1.0-rc.17](../reviews/2026-11-05-rc17-human-test-findings.md). The Linux AppImage now holds its audio plugins, for Play. Your edits now stay when the hosted file changes outside Studio. It comes after 0.1.0-rc.17.

## What changed

### The desktop app on Linux

- The AppImage now holds the audio plugins, so Play does not hang in a local build. The file is larger than before.
- A page that scrolls no longer shows its text through the toolbar.

### A hosted file that changed outside Studio

- **Change:** "Apply My Edits to the New File" replaces "Start Again from the Hosted File". Your edits stay, and the outside changes come in.
- When you and the hosted file changed one field, you select the value to keep. Nothing changes on a file host until you write.
- To remove all edits, select **Discard the Draft**.
- **Read Again** now moves a draft with no edits to the new file. Review then examines the new file.

### Review

- **Change:** **Simplified** now shows only the changes in words, with each time in your local time. **Detailed** shows the lines of the file.
- **Detailed** gives your local time below each changed date.
- A refused write now says where the address came from, what is wrong and what can occur. It also says what changed on a file host and what you can do.
- The self link notice and the return warning also explain themselves.
- The label "Announce" no longer touches its text.

### The size, the type and the duration of an audio file

- **Change:** the **Duration** field moved into **Properties**. The summary shows the size, the type and the duration.
- **Change:** **Properties** shows these values as text. To edit them, select **Advanced**, read the warning and select **Edit Values**. This also applies to a value that is missing. **Lock Values** shows the text again.
- This applies to tracks, to the recording of a live show and to the sheet "Add a track from an address".

### Smaller changes

- After a move, a new `itunes:new-feed-url` tag goes first in the channel, so a person who reads the file finds it. A tag that the feed already has stays in its position.
- A version from an R2 file host no longer shows a quote mark in **Versions**.
- "Lock against import" now has a help text.

## What to test

The screenshots of each change passed. These steps need a real file host, a real computer or the real index.

### The AppImage on your Linux computer

1. Run the AppImage of this candidate. Make sure that your collection stays.
2. Open a track that you did not change, and press Play. Make sure that you hear the audio.
3. Replace the audio of a test track with a new file, and press Play. Make sure that you hear the new audio.
4. Scroll a long page. Make sure that no text shows through the toolbar.

### A hosted file that changed outside Studio

5. On a real file host, start a draft of a test feed, and change its title in Studio.
6. Change the description in the feed file on the file host. Then select **Write to the File Host**.
7. Make sure that Studio does not write. Select **Apply My Edits to the New File**.
8. Make sure that your title stays and the new description comes in. Select **Apply to the Draft**, then write the feed.
9. Repeat with a title change on both sides. Make sure that Studio asks you to select one.

### Read Again

10. Open Review on a test feed with no edits, then close it.
11. On the file host, change `itunes:new-feed-url` to an address that gives no feed.
12. Select **Read Again**, then open Review. Make sure that Studio refuses the write and explains why.
13. Select **Remove the Tag**, then write the feed.

### The computer clock

14. Start the shell with a clock 10 minutes ahead: `faketime -f '+10m' studio-desktop --data-dir FOLDER`. This changes the clock of Studio only. Do not use a large error, because secure connections and R2 requests can then fail.
15. Make a change in a test feed, and open Review. Make sure that the notice says that the clock is ahead, and that the build date is the correct time.

## Known gaps

- No automatic test heard the audio of Play. A local build proved that the AppImage finds its audio sinks.
- The DEB and the RPM use the audio plugins of your system. No test examined Play in them on a computer with no plugins.
- No test of the toolbar correction used a computer with a GPU.
- The screenshots did not cover the new **Properties** on the live show page or in the add sheet. They also did not cover a failed read of the duration.
- A list is one value in a merge. A change of one credit and an outside change of a different credit are thus one conflict. Live shows are also one value.
- When you type a new address in **Audio file address**, the earlier size and duration stay. Select the file with **Choose…** to get new values.
- Apps can stay at an earlier address after a move. The cause in each app is not known.
- The human test of a return waits for a release of Stophammer that holds its ADR 0083. A check in copies of both code sets passed. No deployed node ran it.
- A second return in a wait stays at the earlier address until the crawler reads the feed again. The check did not find how often this occurs.
- ADR 0126 condition 5 does not run, because Stophammer has no lookup of a feed by URL.
- The macOS and Windows installers need a tester with that system.
- The human tests of Phase 12 (the server shell) and of tasks 065 to 084 stay open.
- The human tests of 0.1.0-rc.10 to 0.1.0-rc.16 stay open.
- The server part of the human test of task 086 stays open.
