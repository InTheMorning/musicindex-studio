# Music Index Studio 0.1.0-rc.19

This candidate makes the first Play of the Linux AppImage faster. It also corrects the faults that the [human test of 0.1.0-rc.18](../reviews/2026-11-05-rc18-human-test-findings.md) found so far. It reads feed addresses that have a space. It comes after 0.1.0-rc.18.

## What changed

### Play

- In rc.18, the first Play after each start of the AppImage waited for several seconds, and the app looked frozen. The AppImage now holds only the 25 audio plugins that it needs, so this wait should be much shorter. The file should also be smaller.
- The player now shows "Starting…" while the audio starts.
- The false error "Studio cannot play this file" no longer stays when the audio starts.

### Addresses with a space

- Studio can now read a feed or a file at an address with a space. The feed file keeps its text.
- **New:** the list **Releases** of an artist or a label names each address with a space. **Correct All** changes each space to `%20` in the draft. Review shows the change, and Studio makes it only from that button.
- An audio, image or link field with a space still stops a write, as before.

### The left panel and Releases

- **Change:** the head of the left panel and each row of **Releases** now show the type dot on the art. This is a new shared rule for the three apps.
- A long release title no longer widens the left panel. It now ends with "…".

## What to test

The screenshots of each change passed. These steps need the real AppImage, a real file host or the real index. No test has heard the audio of this file, because the check computer has no sound device.

### The AppImage on your Linux computer

1. Run the AppImage of this candidate. Make sure that your collection stays.
2. Press Play on a track. Make sure that "Starting…" shows, and that you hear the audio soon. Tell us the wait in seconds. In rc.18 it was long.
3. Make sure that no error stays below the player.
4. Play a FLAC file and an M4A file, if you have them. The plugin list is shorter now.
5. Scroll a long page. Make sure that no text shows through the toolbar.
6. Open an artist with a long release title. Make sure that the left panel has no scrollbar, and that each dot shows.

### A hosted file that changed outside Studio

7. On a real file host, start a draft of a test feed, and change its title in Studio.
8. Change the description in the feed file on the file host. Then select **Write to the File Host**.
9. Make sure that Studio does not write. Select **Apply My Edits to the New File**.
10. Make sure that your title stays and the new description comes in. Select **Apply to the Draft**, then write the feed.
11. Repeat with a title change on both sides. Make sure that Studio asks you to select one.

### Read Again

12. Open Review on a test feed with no edits, then close it.
13. On the file host, change `itunes:new-feed-url` to an address that gives no feed.
14. Select **Read Again**, then open Review. Make sure that Studio refuses the write and explains why.
15. Select **Remove the Tag**, then write the feed.

### An address with a space

16. Open an artist feed that has a release address with a space. Select **Correct All**, examine Review and write a test feed.
17. Make sure that the index and a second app still find that release.

### The computer clock

18. Start the shell with a clock 10 minutes ahead: `faketime -f '+10m' studio-desktop --data-dir FOLDER`. This changes the clock of Studio only. Do not use a large error, because secure connections and R2 requests can then fail.
19. Make a change in a test feed, and open Review. Make sure that the notice says that the clock is ahead, and that the build date is the correct time.

## Known gaps

- A CI run gives the first build of the shorter plugin list with this candidate. The time of 0.41 s comes from the rc.18 file with the other plugins taken out, on a virtual screen. Your wait can be different.
- The screenshots did not cover the tile view of **Releases**, a hollow dot on the new locations or these changes in the AppImage.
- The new **Properties** has no screenshot on the live show page or in the add sheet, or for a failed read of the duration.
- A corrected address can differ from what a different tool expects. Correct only feeds that you control. No test examined how apps treat either form.
- The link of an album to its artist gets no notice and no button when its address has a space.
- A merge treats a list as one value. A change of one credit and an outside change of a different credit are thus one conflict.
- Apps can stay at an earlier address after a move. The cause in each app is not known.
- Studio cannot yet delete a feed from a file host. ADR 0131 decides this, and no code holds it yet.
- The human test of a return waits for a release of Stophammer that holds its ADR 0083.
- v4vmm has not examined its rows with art against the new dot rule.
- The macOS and Windows installers need a tester with that system.
- The human tests of Phase 12 (the server shell) and of tasks 065 to 084 stay open.
- The human tests of 0.1.0-rc.10 to 0.1.0-rc.17 stay open, except for the parts that passed.
- The server part of the human test of task 086 stays open.
