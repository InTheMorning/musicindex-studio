# Music Index Studio 0.1.0-rc.20

This candidate lets you move a whole release and keep its old files until you review their deletion. The desktop app can now hold many collections. A page now shows a change that came from outside Studio. The candidate also holds the corrections from [local use on 2026-11-06](../reviews/2026-11-06-local-use-findings.md).

**Before the first start of this candidate on a desktop, make a copy of your data folder.** The first start moves your only copy of the data into a new subfolder. The start does this one time. The table in the [desktop guide](../user-guide/start-on-desktop.md) gives the folder of each system. On Linux, it is `~/.local/share/musicindex-studio`.

## What changed

### Move a release

- **New:** the **Files** page has **Move This Release…**. One sheet shows the plan for the feed file, the audio and the images. The draft gets each change, and Review shows them.
- **New:** the page of a file host has **Move All Releases…**. It makes one change set, with one diff for each release.
- **Change:** a move no longer deletes the old file at the write. **Move to** on one file follows the same rule. The old files stay for the time that you select, 7, 30 or 90 days. The time for **Move to** is 30 days.
- The **Files** page shows each move that waits. When the time is complete, a notice opens **Review the Deletion**. Studio never deletes these files by itself. **Delete Now…** and **Keep the Files** are also there.
- A notice shows when the feed moves and other files of the release stay on the old file host.

### Many collections on the desktop

- **New:** **Settings** has the section **Collections**. You can make, copy, open and delete a collection, and start one from an account file.
- Each new collection has its own vault and passphrase. A copy keeps the passphrase of its source, and it can write to the same real feeds. The sheet warns you about this.
- **Open** restarts the app on that collection. A write that runs gives the dialog with **Open After Write**, **Open Now** and **Cancel**.
- When the open collection is not **Main collection**, the left panel has a blue row with its name.

### Changes from outside Studio

- **New:** when **Releases** or a feed page opens, Studio reads the public feed file. A tile and a notice show "Changed outside Studio" or "Moved outside Studio".
- A feed page also asks musicindex for its address, and it shows a notice when that address is different.
- The check writes nothing. To stop it, clear **Check for outside changes** in **Settings**.

### The size and the shape of the app

- **Change:** with a mouse, Studio now uses the macOS text sizes and control sizes, in the app and in a browser. With touch, nothing changes.
- **New:** **Settings** has **UI scale**, with five levels. A release tile is larger.
- **Change:** the outline of an album now holds only its tracks. The other pages of a feed are tabs on the page, and one select menu on a phone.
- **New:** **Releases** has a reverse icon after the view icons. "Newest" then says "Oldest", and "A to Z" says "Z to A".
- Back and Forward are now filled circles. The focus ring of a field is thinner.
- The Nostr and Artwork rows show a small preview. **A row with a Nostr key now asks the relays for its profile when the page opens.**

### The desktop app

- A left click on the tray icon now opens the window on Linux. The first close asks what a close does, and **Settings** can change the answer.
- On Linux with an NVIDIA card, the app starts itself again one time, so the page loads fast.
- **New:** **Settings** gives the time before the vault locks. The desktop starts at **Never**.
- The player shows the wait before the sound, and the position bar and its cursor now agree.

### Payments and people

- **Change:** one check box at the Write button tells Podcast Index and sends a podping. It replaces the two settings.
- Recipients now have one sheet and sort by split. The share bar shows each large part, and "Other" holds at most 10 %.
- The sheets that add a value have one layout, and they use one search of musicindex.
- On the page of a person, you can edit a wallet, a credit name and a support link. The default address is on its row. A person can be part of many artists and labels.
- A node key no longer shows as a Lightning address. The labels are now "Node address" and "LNURL address". A wrong Nostr key now offers **Correct the Feeds**.
- A row of **Check your feeds** names the tracks. A change set opens with the first diff shown.
- The lists of the People page fold.

### Text

- The warning of an account export now tells the risk. The text of **Lock against import** now tells what the lock does. The **Files** page and **Feed facts** show `itunes:new-feed-url`.

## What to test

The screenshots and the tests of each change passed. These steps need the real AppImage, a real file host, a real device or a deploy.

### The upgrade of your data

1. Make a copy of your data folder.
2. Start the AppImage of this candidate. Make sure that your feeds, your people and your vault stay.
3. Make sure that the data is now in `collections/main/`.
4. If anything is missing, stop and tell us. Do not delete your copy.

### Collections in the AppImage

5. Make a new collection, and select **Open**. Make sure that the app restarts on it, with the Welcome page and the blue row.
6. Open **Main collection** again. Make sure that your feeds are there.
7. Start a real upload. During the upload, select **Open** on a different collection. Select **Cancel**, and make sure that nothing changes.

### A move on real file hosts

8. Connect two real file hosts. Select **Move This Release…** on a test release, with 7 days. Write it.
9. Make sure that the feed and each file play from the new file host. Make sure that the old files stay on the old file host.
10. Open the **Files** page on a later day. Make sure that the days count, and that the musicindex line is correct.
11. Select **Delete Now…**, examine Review and write. Make sure that only the old files go, and that the pointer file stays.
12. Select **Move All Releases…** on a file host with two test releases. Examine each diff, then select **Discard**. Make sure that each draft comes back.

### An outside change on a real file host

13. Change a feed file on the file host, then open **Releases**. Make sure that the tile shows the mark.
14. Open the feed that two of your collections hold. Make sure that the notice gives the correct addresses.

### Play

15. Close the app. Run this command in a terminal, with the name of your file: `GST_DEBUG=2 ./Music_Index_Studio.AppImage 2> play-log.txt`.
16. Press Play on a track, and measure the seconds until you hear the audio. Tell us that time, and send `play-log.txt`.

### The window and the tray

17. On your Linux computer, make sure that a left click on the tray icon opens the window. Close the window, and make sure that the question shows one time.
18. On a computer with an NVIDIA card, make sure that the first page loads fast.

### The server

19. Deploy this candidate. Make sure that an account stays, and that **Settings** on the server has no **Collections**.
20. On your iPhone, open **Releases**, the reverse icon and a feed page with its tabs.

### A profile on a real relay

21. Open a release with a real Nostr key. Make sure that its picture and name show after a short time. Make sure that the page stays usable when your network is off.

## Known gaps

- The move of the first start ran only with a copied folder on a virtual screen. No real upgrade and no AppImage ran it. The macOS path has no test.
- The cause of the wait before Play in the plain binary is not known. A test with a fake audio sink took 0.75 s, and that test did not use WebKit.
- The musicindex line of a move compares only the feed address, so it says nothing about **Move to** on one file. It also does not prove that each app follows a move. The days are a judgment, with no measurement.
- A move does not end by itself. You must return to Studio and review the deletion.
- **Import an Account File…** makes the collection, then you select **Import an Account** on its first page. It is not one step.
- A host or a CDN that changes the bytes of a file can give a false "Changed outside Studio".
- An open move also shows under "Changes to write" on the People page.
- **Move All Releases…** also shows on a file host with no releases. No test examined the result there.
- No connector can set a redirect, so each move gives a pointer file. The interface and the guide also name a redirect.
- Apps can stay at an earlier address after a move. The cause in each app is not known.
- Studio cannot yet delete a feed from a file host. ADR 0131 decides this, and no code holds it yet.
- The human test of a return waits for a release of Stophammer that holds its ADR 0083.
- The search of musicindex finds a feed, not a person. A search for a contributor waits for the new search of Stophammer.
- The macOS and Windows installers need a tester with that system.
- The human tests of Phase 12 (the server shell) and of tasks 065 to 084 stay open.
- The human tests of 0.1.0-rc.10 to 0.1.0-rc.19 stay open, except for the parts that passed.
- The server part of the human test of task 086 stays open.
