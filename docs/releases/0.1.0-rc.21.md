# Music Index Studio 0.1.0-rc.21

This candidate shows where a person is, with the split of each track. A person can link to a page on Music Index. A hidden suggestion can come back. A live show now has a stream check.

**Before the first start of this candidate, make a copy of your data folder.** This candidate adds database schema version 33. Rc.20 and older cannot open data that this candidate opened. They show "the collection has schema version 33, and this Studio knows only 32".

On a desktop, data that is not in the subfolder `collections/main/` moves there at the first start. The move changes your only copy of the data. The table in the [desktop guide](../user-guide/start-on-desktop.md) gives the folder of each system. On Linux, it is `~/.local/share/musicindex-studio`.

## What changed

### Where a person is

- **New:** the page of a person has the section **Where this person is**. Each feed is one entry with a summary line.
- An open entry gives each place: "Album" or the number and title of the track. It also gives the split of the person and the roles of the person there.
- The split follows the share bar. A fee keeps its share, and the others share the rest. Two addresses of a person in one place add their splits.
- The first run after the upgrade fills the new data again from your library copies.
- **Check your feeds** now gives only the state of the check.
- A credit row of **More from your feeds** has its release as its title. One line for each role follows, with its tracks. The sheets **Check**, **Make a Person** and **Add to a Person** use the same row.

### Suggestions

- **Change:** the button **Not This Person** is now **Hide This Suggestion**. It changes no person and no feed.
- **New:** the People page has the fold **Hidden suggestions** at its end. It is closed at first. Select **Show Again** on a row to put the suggestion back in the list.

### A person and Music Index

- **New:** **Link to an Artist or Label Page** opens one sheet. It has the search of Music Index and a fold of the pages of your collection.
- A result that is a feed of your collection makes a link as before. Each other result makes a read-only link. Studio writes nothing to that feed.
- When the page of a person opens, Studio reads each read-only page on Music Index. A new picture, website, Nostr key or wallet shows at its field with **Use**. It is a pending change until you select **Save**.
- A page that Music Index does not know shows a note.
- The export of the people now gives the read-only pages of each person.
- A result that you link keeps its type line and its source line in gray.
- A search row of artist and label feeds now says "N releases", not "N albums".

### The look of the app

- **Change:** the tabs of a feed page, and the source row of the file picker and of **Add tracks**, are one segmented control. The selected segment has a gradient and a top highlight.
- A long label wraps in its segment. At 760 px or less, the tabs stay one select menu.
- The keyboard works in the control. Left and Right move the focus. Home and End go to the ends. Enter or Space selects.
- **New:** the left panel has an accent glow at its top, as on musicindex.org. It stays at the top when the outline scrolls.
- Under **Increase Contrast**, the left panel has no glow.
- A row of the field list for a text field now shows an example, such as `artist:"artist name"`, in the color of a placeholder. A click or Enter puts only the token in the field.
- At a width of 390 px, the sort menu of **Releases** now starts at the left edge of its button.

### A live show

- **Change:** Studio refuses to write a live item with no stream address or no stream type. It also refuses a stream type that does not agree with the address extension.
- A live item with no content link gets a warning, and the write continues.
- **New:** **Stream type** is a menu: HLS, MP3, AAC, M4A, Ogg, DASH and **Other…**. Select **Other…** to type a different type.
- **New:** Studio fills the type from the extension of the address. It stops when you select a type yourself.
- **New:** **Check Stream** has a **Check** button. Studio reads the stream for at most 8 seconds and writes nothing. The line shows "Live", the type and the time, or the cause in orange.
- The check also fills the type. A known different name of a menu type fills that menu type.
- **New:** when you selected a type and the stream server sends a different type, the line shows a warning and a **Use** button. Select **Use** to take the type of the server. The warning does not stop **Go Live** or a write.
- **Change:** **Go Live** checks the stream. When the stream is not live, Studio refuses, and the draft does not change. A grant from a connected app gets the same refusal.
- **Change:** the address check now also covers the fields and the content links of each live item. A stream address with a space is refused, and the field is marked.
- When the first variant playlist of an HLS stream fails, the cause now names the variant.
- A server on the internet cannot check a stream in a private network. It gives a refusal.

## What to test

The screenshots and the tests of each change passed. These steps need the real AppImage, a real stream server, a real device or a deploy.

### The upgrade of your data

1. Make a copy of your data folder.
2. Start the AppImage of this candidate. Make sure that your feeds, your people and your vault stay.
3. Make sure that the data is in `collections/main/`.
4. If anything is missing, stop and tell us. Do not delete your copy.
5. Open a person with a few feeds. Make sure that **Where this person is** shows the correct splits.

### The stream check of a live show

6. Add a live show to a test release. Enter the address of a real HLS stream that is live. Make sure that **Stream type** shows HLS.
7. Select **Check**. Make sure that the line shows "Live", the type and the time.
8. Enter the address of a real Icecast mount. Select HLS in **Stream type**, then select **Check**. Make sure that the warning and **Use MP3** show. Select **Use MP3**, and make sure that the menu shows MP3.
9. Put a space before the stream address. Make sure that the field is marked and that the write stops.

### Music Index with a real network

10. Open a person. Select **Link to an Artist or Label Page**, and link a page that is not in your feeds. Make sure that the row shows "Read only".
11. Save, and open the person again. Make sure that a new picture, website or key shows with **Use**.
12. Hide a suggestion, then open **Hidden suggestions** and select **Show Again**.

### The server

13. Deploy this candidate. Make sure that an account stays.
14. On the server, enter a stream address in a private network, and select **Check**. Make sure that the line gives a refusal.
15. On the server, do the steps of the stream check with real streams. Also select **Go Live** with a stream that is not live, and make sure that Studio refuses.

### The iPhone

16. On your iPhone, open **Releases**, its sort menu with **Oldest** and **Z to A**, and a feed page with its tabs.
17. On your iPhone, open **People**, and select **Z to A** and then **Newest** in its sort menu.
18. On your iPhone, open **Find on Music Index** from a credit sheet. Make sure that no list shows until you tap the field. Type `ki`, and make sure that the list shows `kind:` above the keyboard.
19. Tap `kind:`. Make sure that the keyboard stays open and that the values show.

### Steps that stay open from rc.20

20. Close the app. Run this command in a terminal, with the name of your file: `GST_DEBUG=2 ./Music_Index_Studio.AppImage 2> play-log.txt`.
21. Press Play on a track, and measure the seconds until you hear the audio. Tell us that time, and send `play-log.txt`.
22. On your Linux computer, make sure that a left click on the tray icon opens the window. Close the window, and make sure that the question shows one time.
23. On a computer with an NVIDIA card, make sure that the first page loads fast.
24. Connect two real file hosts. Select **Move This Release…** on a test release, with 7 days. Write it.
25. Make sure that the feed and each file play from the new file host. Make sure that the old files stay on the old file host.
26. Open the **Files** page on a later day. Select **Delete Now…**, examine Review and write. Make sure that only the old files go.
27. Change a feed file on the file host, then open **Releases**. Make sure that the tile shows the mark "Changed outside Studio".
28. Open a release with a real Nostr key. Make sure that its picture and name show after a short time. Make sure that the page stays usable when your network is off.

## Known gaps

- The upgrade to schema version 33 ran on real data with a build of local `main`, not with the AppImage.
- The stream check of a live HLS stream and the check of the server are open. The agent checks used a local test server and a stream that answers 404.
- On 2026-11-10, the stream check passed on the desktop with local `main` and real servers: an Icecast stream that is live, a stream that answers 404, and the Go Live refusal. The type warning with a real Icecast mount did not run.
- The read-only page of a person ran against a test relay and a test file host. Real Music Index with this build did not run.
- The human tests of rc.20 stay open. They are steps 20 to 28, and the parts of rc.20 that this list does not repeat.
- The move of the first start ran only with a copied folder on a virtual screen. The macOS path has no test.
- The field list on a phone was checked only in a desktop browser at phone width.
- The search of Music Index finds a feed, not a person. A search for a contributor waits for the new search of Stophammer.
- The human test of a feed return waits for a deploy and two real file hosts. Stophammer ADR 0083 is live.
- The macOS and Windows installers need a tester with that system.
- The human tests of Phase 12 (the server shell) and of tasks 065 to 084 stay open.
- The human tests of 0.1.0-rc.10 to 0.1.0-rc.20 stay open, except for the parts that passed.
