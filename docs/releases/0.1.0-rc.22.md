# Music Index Studio 0.1.0-rc.22

This candidate gives each person a new page, with lists of pictures and websites. People can update each person from the linked pages on Music Index. The candidate also adds the tab **Check** to each feed, a podping after a move, and Settings with tabs. Each list of rows is now one Tab stop.

**Before the first start of this candidate, make a copy of your data folder.** This candidate adds database schema version 41. Rc.21 and older cannot open data that this candidate opened. They show "the collection has schema version 41, and this Studio knows only 33".

## What changed

### People

- **New:** a person can have a nickname. Only Studio shows it. The official name goes into a new credit. **Change** in the nickname sheet saves at once.
- **Change:** the page of a person starts with its links to artist and label pages, then **Credits**.
- **New:** a person has a list of pictures and a list of websites. Each value shows its source: `From "{title}" on {host}`, or `Added in Studio`. One value of each list has the tag **Default**. Studio puts the default into a new credit.
- **New:** each value has **Remove**. Each value that is not the default also has **Make Default**. **Add a Picture Address** and **Add a Website** add a value. A change stays pending until **Save**.
- A suggestion, **Add All Suggestions** and **Find on Music Index** add a value to its list. They do not change the default. When a list is empty, the new value becomes the default.
- **New:** the People page has **Update from Linked Pages**. The sheet shows each new value of each linked page, with one check box for each value. **Update** adds only the selected values. A value that is in a list does not show again.
- **Change:** **Add a Person** searches People and Music Index in one sheet. Studio makes the person only when you select **Add the Person**.
- **Link to an Artist or Label Page** finds and links a page on Music Index in one sheet. A link gives an empty name the title of the page.
- A linked page suggests only the wallets of its recipient that match the person. The wallets of the other recipients are in a fold that is closed at first.
- Each suggestion button is **Add**.
- **Find on Music Index** is also on a credit that is open.

### Releases and the left panel

- **New:** a publisher feed can add a new album from its **Releases**. The list view of **Releases** can also add a release.
- **New:** the left panel marks the state of each feed. The pencil stays current after each save.
- The first-step row of a publisher feed does not show when the feed has releases.

### The tab Check

- **New:** each feed page has the tab **Check**. It examines the feed and reads the feed in the index of Music Index. It gives each finding and the repair that is possible.

### Files and the release folder

- **New:** each release has a release folder that you can change. Select it with a folder dialog or from a folder list.
- **Change:** the **Files** page has one way to move: **Move This Release…**. A move also takes the new files of a release, and it can replace a file at the feed path.
- A release keeps one library record for each file.
- Each copy of a file has one step to put it in the feed. You can remove the host of one library file.
- **Change:** on a changed file in the release folder, **Restore** is now **Restore the Hosted Copy…**. It is the first button of its row and has the destructive style. A confirmation opens before Studio writes over the local file.

### Moves, Music Index and the podping

- **New:** after a move, Studio sends one podping of the old feed address. The **Files** page shows the state of the podping as a status tag.
- **New:** Review shows how long Music Index waits before it reads a returned feed again. Studio sends the podping after that wait. A podping that was sent has **Send the Podping Again**.
- The notice of a feed that changed outside Studio gives the podping of the last move.

### Collections

- **New:** you control each collection. Each collection row has one **Actions** menu, and the current collection has the badge **Current**.

### Settings

- **Change:** Settings has tabs and one Save bar. **Save** is off when the draft cannot be saved.

### Live shows

- Each problem of a live show shows at its field.
- Review checks the stream type of each changed live stream.
- Studio fills an empty stream type, and names each type with its menu label.
- A show with no stream type gives the next step.

### Credits and merges

- A credit with no name is left out of the feed. Studio refuses an empty credit name.
- A hosted credit tag keeps the order of its attributes.
- A merge conflict shows each value as text above a short select menu. The merge notice gives the times of the change.

### Keyboard and look

- **Change:** each list of rows is one Tab stop. The arrow keys move in the list. This includes the left panel, the file picker and each list of expandable rows.
- Each fold header is a row. Enter closes the field list.
- Each check box has the shared look of the three apps.
- In a row, a destructive button comes first.
- The first row of a list shows its full focus ring.
- The field of each search sheet does not move while results load.
- At 320 px, the narrow bar stays in the window.

### The README

- The README is now a landing page for an artist, with an image of the release page.

## What to test

The screenshots and the tests of each change passed. The human checks of the People page, **Update from Linked Pages**, the podping after a move and **Restore the Hosted Copy…** passed on the desktop with a local build. These steps need the real AppImage, a real device or a deploy.

### The upgrade of your data

1. Make a copy of your data folder.
2. Start the AppImage of this candidate. Make sure that your feeds, your people and your vault stay.
3. Open a person with a picture and a website. Make sure that each one shows in its list with the tag **Default** and the line `Added in Studio`.
4. If anything is missing, stop and tell us. Do not delete your copy.

### People with real Music Index

5. Open **People**, then **Update from Linked Pages**. Clear one check box, then select **Update**. Make sure that only the selected values are in the lists of the person.
6. Open **Update from Linked Pages** again. Make sure that the values of the first update do not show again.
7. Add a person with **Add a Person** from a live page on Music Index. Give a nickname. Make sure that a new credit gets the official name.

### The server

8. Deploy this candidate. Make sure that an account stays.
9. On the server, open a person with two linked pages, and make sure that both lists show their sources.

### The iPhone

10. On your iPhone, open the page of a person. Make sure that each value row, **Remove**, **Make Default** and the tag **Default** fit in the screen.
11. On your iPhone, open Settings and each of its tabs.

### Steps that stay open from rc.21

12. The steps of rc.21 that did not pass stay open: the stream check with a real HLS stream and a real Icecast mount, the steps on the server, the steps on the iPhone, and the steps that rc.21 kept from rc.20.

## Known gaps

- The upgrade to schema version 41 ran on real data with a build of local `main`, not with the AppImage.
- The pictures and websites that you saved before this candidate show `Added in Studio`, because Studio did not record which page gave them.
- The README gates of task 124 stay open: the one-minute read, the image on a phone and a start on a clean computer.
- The search of Music Index finds a feed, not a person.
- The macOS and Windows installers need a tester with that system.
- The human tests of 0.1.0-rc.10 to 0.1.0-rc.21 stay open, except for the parts that passed.
