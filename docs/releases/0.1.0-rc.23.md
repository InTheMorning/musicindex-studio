# Music Index Studio 0.1.0-rc.23

This candidate changes how you delete and move a feed, and how you make a release. A release now starts on the page of its artist, and it has a kind: album, EP or single. Studio also follows a move that a different Studio made, and the review sheet names each deletion.

**Before the first start of this candidate, make a copy of your data folder.** This candidate adds database schema version 42. Rc.22 and older cannot open data that this candidate opened. They show "the collection has schema version 42, and this Studio knows only 41".

## What changed

### Releases and the release kind

- **Change:** a release starts only on the page of its artist, with **＋ Add a Release**. The page "Add feeds" has no row "Album". Its hint says "A release starts on the page of its artist."
- **Change:** the first-step row "Add a release" of a label page asks for an artist page first.
- **New:** the new release gets the link to its artist page. It also gets the hosting pages and the label pages of the newest other release of that artist.
- **New:** a release has a kind. The menu "Kind" has "From the tracks", "Album", "EP" and "Single". With "From the tracks", 1 to 3 tracks give a single, 4 to 6 give an EP, and each other count gives an album.
- The menu "Kind" is in the release form and on the tab **Settings**. A change saves at once and needs no write. The feed file has no tag for the kind, so no app gets it.
- **Change:** the type label of a release shows its kind on the tile, the row, the head of the page and the left panel. A release of 1 to 6 tracks that showed "Album" now shows "Single" or "EP".
- **New:** a release must have a link to an artist page. A playlist or a show feed must have a link to an artist, label or hosting page. The tab **Check** shows "This release has no artist page." or "This feed has no artist, label or hosting page.", with **Link a Page**.
- **New:** Review stops the write of such a feed and shows the same text and **Link a Page**. A delete of the feed file, a hidden feed, a change set and a write of a connected app have no stop.

### Delete and move a feed

- **New:** **Delete from File Host…** opens a sheet that asks "What do you want to do?". The rows are "Put the feed on a different file host", "Take the feed out of the apps" and "Remove the file".
- **New:** the block **Retire** shows three steps: the request to remove the feed, the removal from Music Index, and the delete of the file. **Check Again** reads the state. **Stop Retiring** clears **Hide from apps** in the draft.
- **Change:** Studio deletes a feed file only after Music Index removed the entry. **Delete Anyway** is gone. The row "Remove the file" shows only after the removal.
- **New:** the sheet **Delete the Feed File** names the file host and the path, and shows three points: "Music Index removed the entry", "Studio keeps a copy of the feed" and "You can put the file back later with Put the File Back on this feed". **Delete** stays disabled until you type the title of the feed.
- **New:** **Put the File Back** on a deleted feed opens Review of a restore. The file comes back with **Hide from apps** on.
- **New:** the delete sheets, the block **Retire** and the move sheet show "Keep the domain {host}. If it expires, its new owner can take over this feed and its payments."
- **Fix:** a deleted feed opens as read-only from the copy that Studio keeps, also after a delete on an S3 or R2 file host.
- **Fix:** the page **Files** reads the state of a move again while Music Index gives a different address.
- **Change:** a move with no old files shows the row "Old files" with "None. No waiting time."

### The review sheet

- **Change:** the check box **Send a podping** stays in view in the footer. The row "Announce" gives the address and the time. With the box clear, it says "No announcement. No index learns about this write until it reads the feed by itself."
- **Change:** a move shows "From" and "To", with each file host below its address. Addresses, paths and file host names have the usual text color.
- **Change:** a write of only deletions has the red button **Delete 1 File** or **Delete N Files** first. A delete of the feed file has **Delete the Feed File** first and **Cancel the Delete**.
- **Fix:** a deletion that Studio refuses is a warning with the kind "Not deleted". For a pointer file it says "Studio does not delete this file. It tells the apps the new address of the feed."
- **Fix:** Review says "This feed will be hidden from apps." before the write of a hidden feed.

### A feed that a different Studio moved

- **Fix:** Studio finds the move when the old folder address has a pointer file. The result is "Moved outside Studio".
- **Change:** one warning says "A different Studio moved this feed." It shows the new address, the file host and "The old address has a pointer file."
- **New:** **Follow the Move** changes the collection and writes nothing to a file host. Drafts and versions stay.
- **New:** with no connected file host for the new address, the feed becomes read-only and shows **Connect a File Host…**. After you connect the file host, **Use This File Host** makes the feed editable again.
- **New:** **Move It Back…** follows the move and opens the move sheet with the old file host selected. The return needs Review and a write.
- **Change:** "Changed outside Studio" and "Moved outside Studio" have the warning color and the triangle icon.

### The tab Check

- **New:** **Show the Ways** opens "Music Index Has Another Address", with two ways to correct the address in the index.
- **New:** the warning "A copy pays other people" comes before the other findings. **Show What to Do** opens a report, and **Copy the Report** copies it.
- **New:** the tab shows "Music Index has not read your last write yet." below the findings.
- **Fix:** for a hidden feed with no entry, the tab says "Music Index does not hold this feed."

### People

- **Fix:** **People**, **Update from Linked Pages** and **Export People** are available before the lookups of the Lightning addresses end.
- **Fix:** a linked page that is not in the collection shows "On {host}" below "Read only".
- **Fix:** **Add a Person** keeps the page as the source of its picture and its website.
- **Change:** a wallet address has one menu **Actions** with **Make Default**, **Edit** and **Copy**.

### Live shows

- **New:** **Remove the Show** removes a live show from the draft. Review shows the removal before the write.
- **Fix:** after a discard removes the live show that is open, the page and the top bar show **Live Shows**.

### The phone and narrow columns

- **Fix:** the tabs of a feed and of Settings become a menu when the column cannot hold each label.
- **Fix:** in a narrow group, the label of a field goes above its value.
- **Change:** at 760 px or less, an ellipsis button replaces **Actions** on a wallet address row and on a collection row.
- **New:** on a touch screen at 760 px or less, a short bar at the left edge shows that a swipe goes back. The start page does not show it. The bar is not a control.

### Other

- **Fix:** an image with an `http` address loads from its `https` address. The saved address does not change.
- **Change:** each add action of an artist says **Add a Release**.

## What to test

The tests and the screenshots of each change passed. These steps need the real desktop app, a real file host, a real device or a deploy.

### The upgrade of your data

1. Make a copy of your data folder.
2. Start the AppImage of this candidate. Make sure that your feeds, your people and your vault stay.
3. Look at the tiles of your releases. A release of 1 to 3 tracks shows "Single", and a release of 4 to 6 tracks shows "EP".

### Make a release

4. Open the page of an artist. Select **＋ Add a Release**, set "Kind" to "EP", and make the release. Make sure that the tile shows "EP" and that the left panel shows the release below the artist.
5. Open a release of the group "Not linked". Change its title and open Review. Make sure that Review refuses the write and offers **Link a Page**.

### Delete, put back and move

6. Open **Delete from File Host…** on a test feed. Make sure that the three goals and the domain line with your real domain show.
7. Delete the file of a test feed that Music Index does not hold. Then select **Put the File Back** and write. Make sure that the file is on the file host again.
8. Open Review of a long draft. Make sure that **Send a podping** stays in view.
9. After a move, select **Delete Now…**. Make sure that the red **Delete N Files** is the first button.
10. Remove a test live show with **Remove the Show** and write. Make sure that the feed file has no live item for it.

### The server

11. Deploy this candidate. Make sure that an account stays.
12. On the server, open the feed that the desktop app moved. Select **Follow the Move**. Make sure that the new address and the read-only notice show. Connect the new file host, and select **Use This File Host**.
13. Do one return with **Move It Back…** between two real file hosts, through Review and the write.
14. Open a person with two linked pages. Make sure that each page shows its host and that each picture and website shows its source.

### The iPhone

15. Open the menu of each wallet address row. Make sure that the ellipsis button and the menu fit in the screen.
16. Look at the bar at the left edge in the light theme and the dark theme, also beside an artwork. Swipe back to the start page, and make sure that the bar is gone there.
17. Open Studio in a new tab. Before you touch the page, swipe back. Tell us if the browser leaves Studio.

### Steps that stay open from earlier candidates

18. `docs/reviews/2026-11-14-open-older-human-tests.md` has one walk for the open tests of Phase 12 and of tasks 049 to 093. It leaves out each step that a later record closed.
19. These steps of the walk of 2026-11-14 stay open: the tab **Check** with real Music Index facts in the AppImage, the picture previews of Check E, and the discard of a new live show.

## Known gaps

- The upgrade to schema version 42 ran in tests, not on real data and not with the AppImage.
- The review sheet scrolls slowly in the desktop app with a long draft. The cause is not known.
- A feed that a change set did not change also has no stop for a missing page until that change set closes.
- The page "Add feeds" has no screenshot at 390 px with the new hint.
- A podping for a write of only deletions has no decision.
- Studio does not show the version of the server in its pages.
- The README gates of task 124 stay open.
- The macOS and Windows installers need a tester with that system.
