# Music Index Studio 0.1.0-rc.26

This candidate shows the version of Studio in Settings, with the git revision and the build date. It also keeps a sheet open when the window becomes narrow. It has no new database schema version. Rc.24, rc.25 and this candidate use schema version 43.

## What changed

### Settings

- **New:** the last section of Settings > General shows the version line, for example `Music Index Studio 0.1.0-rc.26 (1a2b3c4, 2026-11-18)`. The line gives the version, the git revision and the build date (musicindex ADR 0083). You can select the text, and the copy button copies the line for a bug report. On the server, the line starts with `Music Index Studio server`.
- **New:** `--version` and the start message of `studio-desktop` and `studio-server` give the same line. The status route gives `version`, `git_revision` and `built_at`.

### Sheets and pages

- **Fix:** the sheets Review and Versions stay open when the window becomes narrow. Before, a change of the window width closed them. Rc.24 and rc.25 have this fault.
- **Fix:** a long folder name in the sheet Release Folder breaks on a new line in the window.
- **Change:** each row of the value routes gives its address on line 2 (musicindex ADR 0082).

### Writes

- **Change:** a write that only removes items sends no podping (ADR 0198 items 16 and 17).

## What to test

The tests and the screenshots of each change passed. These steps need the real desktop app, a real file host, a real device or a deploy.

### Settings

1. In the desktop app, open Settings > General. Make sure that the last section shows `Music Index Studio 0.1.0-rc.26`, a git revision and a date in parentheses. Select the text of the line. Then select the copy button, and paste into a text editor. Make sure that the pasted text is the full line.
2. On `studio.musicindex.org`, do step 1 again. Make sure that the line starts with `Music Index Studio server 0.1.0-rc.26` and has a git revision.
