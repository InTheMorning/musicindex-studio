# Music Index Studio 0.1.0-rc.27

This candidate makes the first release of a new artist easier. Review shows the result of a write and can link a missing page. A release page shows what the release needs. Each error tells the next step. A merge of two persons has an undo. The database schema version changes from 43 to 44.

## What changed

### Writes and Review

- **New:** after a write of one feed, Review stays open and shows the result. The result gives the host and the public address with Copy. When listeners cannot get the feed yet, the result shows "Listeners cannot get it yet." and the button "Put It Online…". That button opens File hosts with the form of the host (ADR 0217).
- **New:** when Review refuses a write because a page is missing, Review has a page menu and "Link and Continue". With no page to select, Review opens the form that makes an artist page, and Studio links the release to the new page. The result names the page that has a changed draft because of the link (ADR 0218).
- **New:** for a payment change, the Simplified view of Review gives one row for each recipient, with the address, the type and the percentage (task 182).
- **Fix:** the button "Connect a File Host…" of the read-only notice opens File hosts. Before, the button had no effect.

### Releases

- **New:** a release page shows "This release needs {n} things" with rows for tracks, cover, audio file and recipient. Each row opens the step that adds the missing item (ADR 0219).
- **New:** Releases and each feed group have a search field. A row stays when its title, or the title of its artist or label page, has the text (ADR 0223).
- **New:** when Music Index has the feed, the header of a release page shows "Open on musicindex.org" (ADR 0220).
- **Change:** a new release with no track shows the kind "Release". Before, it showed "ALBUM", and then "SINGLE" after the first track (ADR 0223).

### Payments

- **New:** each "Type" menu of an address shows a panel that explains the type, with an example. "LNURL Address" is the first item, and a new recipient starts with it. Each type has its own address field (ADR 0217, ADR 0219).
- **New:** a form refuses an address that does not agree with its type. When the address agrees with the other type, the field has "Use LNURL Address" or "Use Node Address".
- **New:** a split has the menu "Shares" or "Percent". The line below the field shows the other value (ADR 0223).
- **Change:** "Add recipients" adds the payment block only with its first recipient. A close with no recipient does not change the draft (task 180).

### People

- **New:** after a merge, the person page shows a notice with Undo. A change to one of the two persons removes the undo (ADR 0217).
- **Change:** the merge sheet, the sheet "Check: {name}" and the payee sheet start on "Select a person". The primary button stays disabled until you select a person (ADR 0218).

### Errors and texts

- **New:** an error notice gives the name of the step that did not complete and a step to correct it. The raw text is in a closed fold "Details". The notice has "Try Again" when a second try can help. A list that does not load shows "Studio could not load {list}." with "Try Again" (ADR 0222).
- **New:** the author fields, the podping check box, Value Routes, the split field and "Payees with no person" have one hint line each (ADR 0222).

### First run and phone

- **Change:** the first-run sheet has two stages, "Your name" or "Label name", and "Where it lives". The button that makes the page is "Make the Page" (ADR 0222).
- **New:** in the desktop app, the first-run library sheet has the button "Choose Folder…" (ADR 0223).
- **Change:** on a phone, the root page shows Releases, People, File hosts and Settings before the feed groups. One tap on a release opens its page. The button "Sections" opens the outline (ADR 0223).

### Packages

- **New:** `packaging/arch/PKGBUILD` builds the Arch package `musicindex-studio-git` from the Git source. No release workflow builds it. `docs/runbooks/arch-package.md` gives the steps (ADR 0216).
- **Change:** the `.deb` and the `.rpm` recommend `xdg-utils`. When no app opens a link, the app shows a dialog with the address and the package name.

## What to test

The tests and the screenshots of each change passed. These steps need the real desktop app, a real file host, a real device or a deploy.

### Upgrade

1. Start the rc.27 desktop app on your real collection. Make sure that Releases and People open with all of your feeds and persons. This step does the upgrade to schema version 44 on real data.

### Desktop app

2. Start the desktop app with a new home folder. On the first-run library sheet, select "Choose Folder…". Make sure that the dialog of the system opens at your home folder. Select a folder. Make sure that the field shows that folder (task 189).
3. Change a release that has a real file host, and write it. Make sure that Review stays open and shows the public address. Select Copy, and paste the address into a browser. Make sure that the feed opens.
4. Open a release that Music Index has. Make sure that the header shows "Open on musicindex.org". Select it, and make sure that the browser opens the release on musicindex.org.

### Phone

5. On your iPhone, open `studio.musicindex.org`. Make sure that the root page shows Releases, People, File hosts and Settings before the feed groups. Tap a release. Make sure that its page opens with one tap. Tap "Sections", then tap a part.

   Use Back two times. Make sure that Back goes to the outline, and then to the release page.

### Arch package

6. On the Arch computer, build and install the package with the steps of `docs/runbooks/arch-package.md`. Start Music Index Studio from the application menu. Make sure that the window shows the UI and that a track plays (ADR 0216).

## Known gaps

- The upgrade to schema version 44 passed in the tests. Nobody did the upgrade with the AppImage or on real data.
- Nobody installed the `.deb` or the `.rpm` on a host with no `xdg-utils`. The dialog of ADR 0216 item 4 has no person check.
- The screenshot walk opens 52 of the 58 sheets. The 6 sheets of `collections` need the Tauri app, and the walk does not start it.
- The review sheet scrolls slowly in the desktop app with a long draft. The cause is not known (task 169).
- The README gates of task 124 stay open.
- Two journey findings have no decision. Check shows a missing artist page as a notice, but Review stops the write. A link to an artist page changes two drafts.
