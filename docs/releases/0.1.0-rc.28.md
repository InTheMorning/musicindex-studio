# Music Index Studio 0.1.0-rc.28

This candidate adds Undo and Redo, and an Undo notice after a delete. A person page has four tabs. Check shows a missing artist page as a stop, and a new release opens "Add tracks". This candidate also corrects the findings of the rc.27 human check. The database schema version changes from 44 to 45.

## What changed

### Undo and Redo

- **New:** the feed editor, the person page and Settings have the buttons **Undo** and **Redo** in the bar, at the left of the draft status. Ctrl+Z gives Undo. Ctrl+Shift+Z and Ctrl+Y give Redo. On a Mac, Cmd replaces Ctrl (ADR 0227).
- **New:** typing in one field is one step. A button, a check box, a select menu or a drag is one step. The history stays while the app is open. A write, **Discard** or **Save** clears it.
- **New:** after **Delete Person** and **Remove from Collection**, a notice with **Undo** shows for 10 seconds. A change of the menu **Kind** or of a nickname also shows this notice. The confirmation sheets stay.
- **Change:** when a feed has pending files or pending host operations, **Remove from Collection** gives no Undo. Its confirmation sheet says "This cannot be undone."
- A write to a file host, a podping and a Nostr publish have no undo. Use **Versions** to go back to an earlier version of a written feed.

### Releases and Check

- **New:** the findings have the level **Stop**. A missing artist page or publisher page has this level. The Check tab shows a stop first, with the mark "Stops the write" (ADR 0224).
- **New:** the checklist of a release has the row "Artist page", with **Link a Page** when the page is missing.
- **New:** **Make the Release** with no track opens the release page and the sheet "Add tracks". The checklist button **Add Tracks** also opens this sheet.
- **Change:** the first tab of a release is "Release" for each kind. The heading of its first section is the kind: "Release", "Album", "EP" or "Single" (ADR 0225).
- **Fix:** the row "Nostr profile" and the row "Artwork" keep an area for the picture while it loads. Before, the row grew when the picture came.

### People

- **New:** the person page has four tabs: **Profile**, **Feeds**, **Payment** and **Settings**. The picture, the name and the Nostr keys stay above the tabs. **Save** and **Discard** apply to all tabs (ADR 0226).

### Layout and navigation

- **Change:** on the root page, People, File hosts and Settings come after the feed groups in the narrow and the wide layout. Before, the narrow layout showed them first (ADR 0226).
- **Change:** the home button and the title add the root page as a new history entry. Back then opens the page that you left, and Forward has no page (musicindex ADR 0080 R-TITLE-1).
- **Fix:** in Review, the check box "Send a podping" and its hint are at the right, directly above "Write to the File Host" (ADR 0205).

### Payments

- **Fix:** on the tab **Value Routes**, a recipient stays in its position when you set or clear **Fee**. It moves to its group when the focus leaves the row (ADR 0144).
- **Change:** "＋ Add a recipient" is after the fees and the fee line.
- **Fix:** in the desktop app and in Safari, the type panel of "LNURL Address" showed a very large "@" icon. Studio gives each icon a dimension (musicindex ADR 0065 R-FIT-7).

### Writes

- **Fix:** after a write with **Send a podping**, the notice stays until Music Index reads the write. Before, the notice disappeared when Music Index did not hold the feed at that time, and the confirmation did not show. After the time limit, the notice gives **Check Again** (ADR 0175).

### Desktop app and packages

- **Fix:** in the desktop app, a click on "Open on musicindex.org" and on the feed address opens the browser. Before, the click did nothing (ADR 0124).
- **Change:** "Choose Folder…" starts at the folder in the field when that folder exists, else at its nearest parent folder (ADR 0226).
- **Change:** the installed program is `musicindex-studio-desktop` in the Arch package, the `.deb`, the `.rpm` and the AppImage. Before, it was `studio-desktop-app` (ADR 0226).

## What to test

The tests and the screenshots of each change passed. These steps need the real desktop app, a real file host, a real device or a deploy.

### Upgrade

1. Start the rc.28 desktop app on your real collection. Make sure that Releases and People open with all of your feeds and persons. This step does the upgrade to schema version 45 on real data.

### Desktop app

2. Open a release, and type in the title field. Press Ctrl+Z. Make sure that the title goes back, and that **Redo** becomes available. Press Ctrl+Shift+Z. Make sure that the typed text comes back (ADR 0227 item 9).
3. Open a test person, and select **Delete Person**. Select **Delete the Person** in the confirmation sheet. Select **Undo** in the notice before 10 seconds. Make sure that the person comes back with the same feeds and payment.
4. On the first-run library sheet or the folder sheet of the Files page, type a folder that exists. Select "Choose Folder…". Make sure that the dialog opens at that folder (ADR 0226 item 1).
5. Open a release that Music Index has. Click "Open on musicindex.org". Make sure that the browser opens the release on musicindex.org.
6. Write a real feed with **Send a podping** on. Make sure that the notice stays and that it becomes the confirmation "Music Index has your write of {time}." Music Index can need some minutes.
7. Open a recipient, and set the type "LNURL Address". Make sure that the icon in the type panel is small.

### Arch package

8. Build and install the package with the steps of `docs/runbooks/arch-package.md`. Start Music Index Studio from the application menu. Make sure that the window opens, and that the task bar shows one Studio window (ADR 0226 item 6).

### Phone

9. On your iPhone, open `studio.musicindex.org`. Open a person. Make sure that the four tabs show, and that the bar shows **Undo** and **Redo**. Change the nickname, and tap **Undo**. Make sure that the nickname goes back.
10. Open a release and its outline "Sections". Tap the title to open the root page. Swipe back. Make sure that the outline opens again. Swipe forward, and make sure that Studio does not move.
11. Open a person, and tap **Add a Wallet**. Make sure that the icon in the type panel is small.

### Steps that stay open from earlier candidates

12. Steps 6 and 7 of the notes of rc.23 (delete and put back the file of a test feed) stay open. The agent did the sheet part of step 6.
13. Steps 12, 13 and 19 of the notes of rc.23 stay open.
14. Step 11 of the notes of rc.24 (the Tab order at a narrow width) stays open.
15. `docs/reviews/2026-11-14-open-older-human-tests.md` has the open tests of Phase 12 and of tasks 049 to 093.

## Known gaps

- The upgrade to schema version 45 passed in the tests. Nobody did the upgrade with the AppImage or on real data.
- An Arch package of rc.27 installed the program `studio-desktop-app`. A menu entry or a script that starts that name must change to `musicindex-studio-desktop`.
- Nobody installed the `.deb` or the `.rpm` on a host with no `xdg-utils`.
- The screenshot walk opens 52 of the 58 sheets. The 6 sheets of `collections` need the Tauri app, and the walk does not start it.
- The review sheet scrolls slowly in the desktop app with a long draft. The cause is not known (task 169).
- In a new Safari tab on the iPhone, a back swipe before a touch opens the root page of Studio. A forward swipe after it does nothing. The cause is not examined (finding 15 of the rc.27 check).
- The README gates of task 124 stay open.
