# Music Index Studio 0.1.0-rc.29

This candidate corrects the findings of the rc.28 human check. The undo of a delete, of the menu **Kind** and of a nickname moves to the buttons **Undo** and **Redo** in the bar. The podping notice stays until **Dismiss**. Review shows the XML changes first. Studio lets you delete a leftover copy of a feed. The database schema version stays 45.

## What changed

### Undo and Redo

- **Change:** these operations show no notice at the bottom of the window: Delete Person, Remove from Collection, the menu **Kind** of a release and the nickname of a person. Their undo is in the buttons **Undo** and **Redo** of the bar, and in Ctrl+Z and Ctrl+Shift+Z (ADR 0228 items 1 and 2).
- **Change:** after Delete Person, the People bar shows "{name} is deleted." with **Undo** and **Redo**. After Remove from Collection, the Releases bar shows "{title} is removed from your collection." **Redo** does the delete again with no confirmation sheet (ADR 0228 item 3).
- **Change:** the undo of a delete stays while the app is open. The next delete replaces it (ADR 0228 item 4).
- **Fix:** the buttons **Undo** and **Redo** stay at one position when the draft status at their right changes its text (ADR 0227 item 2).

### Writes and Review

- **Change:** the notice after a write with a podping has **Dismiss** in each state. It stays until you select **Dismiss** or leave the page. The confirmation "Music Index has your write of {time}." keeps the height of the notice before it (ADR 0228 items 8 to 10).
- **Change:** in Review, the XML changes come first. The file operations are in a fold "File operations ({n})" that is closed when the sheet opens. The error of a write shows in the footer, directly above "Send a podping" (ADR 0228 items 14 to 16).
- **Fix:** a write stopped with "a file exists at {path} already" when the file host had a file with the same bytes at the upload path. The write now compares the SHA-256 of that file with the library file. With the same SHA-256, the write uses the file and continues. With a different SHA-256, it stops as before (ADR 0034).

### Delete a feed file

- **New:** when Music Index holds the GUID of the feed at a different address, the file is a leftover copy. The sheet "What do you want to do?" then shows the delete row. It also shows the line "Music Index reads this feed from {address}. This file is a leftover copy." This does not apply when Studio moved the feed from the address of Music Index to this file (ADR 0228 items 20 to 22).

### Releases

- **Change:** on a phone, the button "Sections" has the name "‹ Overview". It is at the left of the tab menu of a release, not in the bar (ADR 0228 item 11).
- **Change:** the tab of the findings has the label "Issues ({n})", for example "Issues (3)". With no finding, the label is "Issues" (ADR 0228 item 13).
- **Change:** on the page of an artist or a label in the wide layout, the release rows have an indent below the artist row (ADR 0228 item 19).

### People

- **Change:** a Nostr key that you added shows no source text. A key that Studio found keeps its source, for example "Found in a Nostr profile" (ADR 0228 item 17).
- **Change:** a person with a linked page shows "Find Another Page" as a small link in the role line. A person with no linked page keeps the button "Find on Music Index" (ADR 0228 item 18).

## What to test

The tests and the screenshots of each change passed. These steps need the real desktop app, a real file host, a real device or a deploy.

### Desktop app

1. Start the rc.29 desktop app on your real collection. Make sure that Releases and People open with all of your feeds and persons.
2. Open a test person, and select **Delete Person**. Select **Delete the Person** in the confirmation sheet. Wait more than 10 seconds. Select **Undo** in the bar of People. Make sure that the person comes back with the same feeds and payment.
3. Write a real feed with **Send a podping** on. Make sure that the notice stays and that it becomes the confirmation "Music Index has your write of {time}." with the same height. Music Index can need some minutes. Select **Dismiss**, and make sure that the notice goes.
4. Open the feed of Nathan Abbott at `https://files.heycitizen.xyz/Songs/Albums/nathan-abbott-everything/nathan-abbott-everything.xml`. Select the delete of the feed file. Make sure that the sheet shows "Music Index reads this feed from https://headstarts.uk/msp/publisher-feeds/nathan-abbott-everything.xml. This file is a leftover copy." and the delete row. Delete the file only if you do not need it.
5. Write the test release at `https://files.heycitizen.xyz/Songs/Albums/TestAlbum/test.xml` again, with the return to the earlier address. Make sure that the write does not stop at `TestAlbum/test/cloned.mp3` (finding 10 of the rc.28 check).
