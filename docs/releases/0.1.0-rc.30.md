# Music Index Studio 0.1.0-rc.30

This candidate corrects findings from the rc.29 human checks. One **＋ Add** menu makes releases and pages, and each form starts with **Find on Music Index**. A found feed can be copied with its tracks and payment recipients. A new release can write its artist page from the same Review. Each group below an open feed has an add row, and a new feed opens at the level where you made it. The database schema version changes from 45 to 50.

## What changed

### Releases and pages

- **New:** Releases has one **＋ Add** menu: **Release**, **Artist**, **Label**, **Show** and **Playlist**. Artist, label and hosting pages have the same menu. The page **Add One You Have** is removed (ADR 0230 items 1 to 4, ADR 0233 item 1).
- **Change:** the button at the head of an artist page says **Artist Page**. Other page types use their type, for example **Label Page** (ADR 0230 items 6 and 7).
- **Change:** the new release form shows its artist page first, with **Change…** or **Select…**. With “No artist page”, **Make the Release** stays disabled. The sheet says “New release for {parent}” or “New release”. Only artist pages can be parents (ADR 0230 items 8 to 10, ADR 0231 item 6).
- **New:** each add form starts with **Find on Music Index**. It replaces “Start from”. The search shows the results of the kind of the form. Below the results, **Add from a File Host Folder…** and **Add from MSP 2.0 Backups…** open the import flows. A feed address in the search field reads that feed (ADR 0233 items 2 to 4).
- **New:** a selection copies the found feed: its values, its tracks with their enclosure addresses, and its payment recipients. The form says “Copies {n} tracks and {m} payment recipients from {title}.” The new release gets its own guid. Studio copies no audio file. When the author is not the name of the parent, the form tells you to examine **Value Routes** before the write (ADR 0233 items 8 to 12).
- **New:** a found feed on a connected file host is added as it is, with no copy. A found feed that is in Studio opens. In the release form, an artist row shows the releases of that artist with **‹ Results** (ADR 0233 items 6, 7 and 13).
- **Change:** a form with no file host shows **Connect a File Host** (ADR 0233 item 5).
- **Change:** when Studio cannot read the found feed file, the form fills the title, the artist name, the artwork and the website. It says that no tracks and no payment recipients are copied (ADR 0233 item 14).
- **Fix:** **Remove from Collection** of a release also removes its remote item from the draft of each page whose written file does not name the release. A link that the written file of the page has stays. **Undo** gives the release and the drafts back (ADR 0233 item 15, ADR 0234 item 11).
- **New:** a release row below an artist page shows “Artist: {name}” when the artist name of the release is not the name of the page (ADR 0234 items 9 and 10).
- **Change:** the sort menu says **Page Order** and **Page Order, Reversed** (ADR 0231 items 4 and 5).

### The left panel

- **New:** groups below an open feed end with **＋ Add release**, **＋ Add artist** or **＋ Add label**. A group with no rows also shows its heading and its add row. Narrow pages show the same groups and actions (ADR 0232 items 1 to 7).
- **Fix:** a new release or page returns to the level where you made it. A release made below HeyCitizen shows **‹ HeyCitizen**. A release made from Releases shows **‹ Releases** (ADR 0232 item 8).
- **New:** an artist that you make below a label shows below it in Studio immediately, before the two pages share a release. Other apps show the artist below the label only after a shared release. When you remove one of the two pages, Studio removes this link. **Undo** gives it back (ADR 0232 items 9 to 12).
- **Change:** a click on a row with the mark “Not checked” also starts its check. This applies to the head of an open feed too. During the check, its mark says “Checking”. A deleted feed gets no “Not checked” mark. A write starts a new check (ADR 0230 items 17 to 19).

### Review and writes

- **New:** Review of a new release offers “Also write {title}” for linked pages with changes. Each check box is on and disabled: “A new release is written with its pages.” Review shows the page changes below it. **Write to the File Host** writes the release first, then the selected pages. “Send a podping” applies to these writes (ADR 0231 items 7 and 8).
- **Fix:** Review **Simplified** shows no heading with no text above the remote items (ADR 0230 item 21).
- **Change:** if the write of a page fails, Review says “Studio could not write {title}.” The release stays written (ADR 0231 item 9, ADR 0234 items 3 and 4).
- **New:** when the written file of a page does not name a written release that names the page, **Issues** of the release says “{page} does not list this release.” **Write {page}…** adds the link to the draft of the page and opens its Review. The release row below the page shows “⚠ {page} does not list it yet” (ADR 0234 items 5 to 8).
- **Change:** Review of a release that was never written shows **Remove from Collection…** in the place of **Discard the Draft**. A failed discard says “Studio could not discard the draft.” (ADR 0234 items 1 and 2).
- **Fix:** Studio can make a release when its artist, label or hosting page has no draft (ADR 0231 item 11).
- **Change:** **Send the Podping Again** shows when a podping fails or the wait ends with no reply. A sent podping has no button during the initial wait. The button stays on the same line, and the notice keeps its height. Narrow lines with this button hide the address (ADR 0229 items 4 to 7).

### File hosts and moves

- **Fix:** **Follow the Move** and **Use This File Host** also correct **Media files** when one connected file host has each media address. With no such file host, the media file host stays as before (ADR 0229 items 1 to 3).
- **Fix:** when you discard a move, cancel a move in Review or remove the last operation of a move, the earlier media file host comes back. **Move All Releases** sets the media file host to the target at the write. A discard of a change set puts back the media file host too. A move plan includes old copies when the target has the files too. A move that adds nothing to the draft sets the media file host at once, and the update to schema 50 clears an earlier media file host that no draft uses (ADR 0234 items 12 and 13). When **Delete from File Host…** opens, it shows no error from the last try (ADR 0230 items 20 to 24).
- **Fix:** **Library files** joins duplicate remote rows to their matching library files. This also repairs the rows with a name that ends in “ 2”. A move can then send the file from the library. A missing remote file says “Not on {host}. Studio cannot download it.” The plan offers no download for that file (ADR 0231 items 12 to 17).

### Delete and restore

- **Change:** delete sheets say “Music Index does not hold this feed.” This also covers a new feed that Music Index has not read (ADR 0230 items 25 and 26).
- **Fix:** each deleted release offers **Put the File Back** and **Check Again**. A notice below the head shows these actions on each tab. When you put the file back, the release gets its file host and path again. A deleted release shows no **Use This File Host** notice (ADR 0230 items 27 to 30, ADR 0231 items 1 and 2).
- **Fix:** the delete of a file removes the empty folders on local and SFTP file hosts. Studio keeps the root folder and each folder that has content (ADR 0229 items 8 to 11).
- **Fix:** **Remove from Collection** does not show an error after a removal that cannot be undone. Removal and **Undo** also work after the collection moves its files into the library (ADR 0227 items 16 and 17). After **Undo** or **Redo**, Releases and the left panel show the change at once (ADR 0228 item 4).

### People

- **Fix:** a person with only a read-only page link shows **Find Another Page** in the role line (ADR 0228 item 18).

## What to test

The tests and the screenshots of each change passed. `docs/reviews/2026-11-20-rc29-human-check.md` gives the desktop steps that passed already. The steps that follow need the real desktop app, a real file host, a real device or a deploy. The agent checks before the desktop check of rc.30, in the same review file, cover the add rows, the label link, a restart and the undo of a remove.

### Desktop app

1. Start the rc.30 desktop app on your collection. Make sure that Releases and People keep your feeds and persons.
2. Open the level of HeyCitizen. Select **＋ Add release** at the end of the group Releases. Make sure that the form starts with HeyCitizen as the parent. Select **Find on Music Index**, then a release of another artist. Make sure that the form shows the copy line and the payments warning. Make the test release. Make sure that its back row is **‹ HeyCitizen**, and that its row in the level of HeyCitizen shows “Artist: {name}”. In Review, examine its tracks, its payment recipients, its artwork and its website before the first write. Make sure that “Also write HeyCitizen” is on and disabled. Then select **Remove from Collection…** in Review, and make sure that the artist page has no draft for it.
3. Repair the test album first: **Move This Release…**, “Media files only”, to bastone. Make sure that Review has nothing to write and that **Media files** says bastone. Then prepare a test move to another real file host with **Move This Release…**. Select **Add to the Draft**. Discard the draft. Make sure that **Media files** says bastone again.
4. Plan a move where the target has the media files and a different host keeps old copies. Make sure that “Old files” and its deletion check box show.
5. Write a test feed with “Send a podping” on. Make sure that **Send the Podping Again** stays hidden during the initial wait. If Music Index gives no reply after 5 minutes, make sure that the button shows and that the content below it does not move.
6. Open a deleted test release on **Settings**. Make sure that **Put the File Back** and **Check Again** show below the head.
7. Remove an unneeded test release with **Remove from Collection**. Make sure that Studio completes the removal without an error.

- The six collection sheets need the Tauri app check.

- The README gates of task 124 stay open.
