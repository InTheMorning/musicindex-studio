# Music Index Studio 0.1.0-rc.30

This candidate corrects findings from the rc.29 human checks. One **＋ Add** menu makes releases and pages. A new release can write its artist page from the same Review. Deleted releases show **Put the File Back** below the head. Each group below an open feed has an add row, and a new feed opens at the level where you made it. The database schema version changes from 45 to 47.

## What changed

### Releases and pages

- **New:** Releases has one **＋ Add** menu: **Release**, **Artist**, **Label**, **Show**, **Playlist**, then **Add One You Have…**. Artist, label and hosting pages have the same menu (ADR 0230 items 1 to 4).
- **Change:** the button at the head of an artist page says **Artist Page**. Other page types use their type, for example **Label Page** (ADR 0230 items 6 and 7).
- **Change:** the new release form shows its artist page first, with **Change…** or **Select…**. With “No artist page”, **Make the Release** stays disabled. The sheet says “New release for {parent}” or “New release”. Only artist pages can be parents (ADR 0230 items 8 to 10, ADR 0231 item 6).
- **New:** **Find on Music Index** fills a new release from a search result. It replaces “Start from”. Results say “Release” or “Release · {artist}”. A selection fills **Title** and **Artist name**, It can also fill the artwork and the website. It copies no tracks (ADR 0230 items 11 to 16, ADR 0231 item 3).
- **Change:** the sort menu says **Page Order** and **Page Order, Reversed** (ADR 0231 items 4 and 5).

### The left panel

- **New:** groups below an open feed end with **＋ Add release**, **＋ Add artist** or **＋ Add label**. A group with no rows also shows its heading and its add row. Narrow pages show the same groups and actions (ADR 0232 items 1 to 7).
- **Fix:** a new release or page returns to the level where you made it. A release made below HeyCitizen shows **‹ HeyCitizen**. A release made from Releases shows **‹ Releases** (ADR 0232 item 8).
- **New:** an artist that you make below a label shows below it in Studio immediately, before the two pages share a release. Other apps show the artist below the label only after a shared release. When you remove one of the two pages, Studio removes this link. **Undo** gives it back (ADR 0232 items 9 to 12).
- **Change:** a click on a row with the mark “Not checked” also starts its check. This applies to the head of an open feed too. During the check, its mark says “Checking”. A deleted feed gets no “Not checked” mark. A write starts a new check (ADR 0230 items 17 to 19).

### Review and writes

- **New:** Review of a new release offers “Also write {title}” for linked pages with changes. Each check box starts on. Review shows the page changes below it. **Write to the File Host** writes the release first, then the selected pages. “Send a podping” applies to these writes (ADR 0231 items 7 and 8).
- **Change:** with “Also write {title}” off, that page keeps its changes. If its write fails, Review says “Studio could not write {title}.” The release stays written (ADR 0231 items 9 and 10).
- **Fix:** Studio can make a release when its artist, label or hosting page has no draft (ADR 0231 item 11).
- **Change:** **Send the Podping Again** shows when a podping fails or the wait ends with no reply. A sent podping has no button during the initial wait. The button stays on the same line, and the notice keeps its height. Narrow lines with this button hide the address (ADR 0229 items 4 to 7).

### File hosts and moves

- **Fix:** **Follow the Move** and **Use This File Host** also correct **Media files** when one connected file host has each media address. With no such file host, the media file host stays as before (ADR 0229 items 1 to 3).
- **Fix:** when you discard a move, the earlier media file host comes back. A move plan includes old copies when the target has the files too. When **Delete from File Host…** opens, it shows no error from the last try (ADR 0230 items 20 to 24).
- **Fix:** **Library files** joins duplicate remote rows to their matching library files. This also repairs the rows with a name that ends in “ 2”. A move can then send the file from the library. A missing remote file says “Not on {host}. Studio cannot download it.” The plan offers no download for that file (ADR 0231 items 12 to 17).

### Delete and restore

- **Change:** delete sheets say “Music Index does not hold this feed.” This also covers a new feed that Music Index has not read (ADR 0230 items 25 and 26).
- **Fix:** each deleted release offers **Put the File Back** and **Check Again**. A notice below the head shows these actions on each tab. When you put the file back, the release gets its file host and path again. A deleted release shows no **Use This File Host** notice (ADR 0230 items 27 to 30, ADR 0231 items 1 and 2).
- **Fix:** the delete of a file removes the empty folders on local and SFTP file hosts. Studio keeps the root folder and each folder that has content (ADR 0229 items 8 to 11).
- **Fix:** **Remove from Collection** does not show an error after a removal that cannot be undone. Removal and **Undo** also work after the collection moves its files into the library (ADR 0227 items 16 and 17).

### People

- **Fix:** a person with only a read-only page link shows **Find Another Page** in the role line (ADR 0228 item 18).

## What to test

The tests and the screenshots of each change passed. `docs/reviews/2026-11-20-rc29-human-check.md` gives the desktop steps that passed already. The steps that follow need the real desktop app, a real file host, a real device or a deploy.

### Desktop app

1. Start the rc.30 desktop app on your collection. Make sure that Releases and People keep your feeds and persons.
2. Open a person with only a read-only page link. Make sure that **Find Another Page** shows in the role line.
3. On a label level, select **＋ Add artist**. Make the artist page. Make sure that it shows below the label immediately.
4. Close Studio. Start Studio again. Make sure that the new artist stays below the label and that its back row names the label.
5. On that artist page, select **＋ Add release**. Make a test release. Make sure that its back row names the artist.
6. Remove a test artist from the collection. Use an artist with no open file operations. Select **Undo**. Make sure that the artist returns below its label.
7. Prepare a test move between real file hosts with **Move This Release…**. Select **Add to the Draft**. Discard the draft. Make sure that **Media files** names the earlier file host.
8. Plan a move where the target has the media files and a different host keeps old copies. Make sure that “Old files” and its deletion check box show.
9. Write a test feed with “Send a podping” on. Make sure that **Send the Podping Again** stays hidden during the initial wait. If Music Index gives no reply after 5 minutes, make sure that the button shows and that the content below it does not move.
10. Make a test release from **Find on Music Index**. Examine its artwork and website in Review before the first write.
11. Open a deleted test release on **Settings**. Make sure that **Put the File Back** and **Check Again** show below the head.
12. Remove an unneeded test release with **Remove from Collection**. Make sure that Studio completes the removal without an error.
